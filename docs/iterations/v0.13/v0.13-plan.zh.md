# v0.13 最小可运行 MVP 计划

英文源文件：`v0.13-plan.md`。

状态：documentation preparation / active child 0.13.1

## 版本目标

构建并独立验证一条确定性、单 Session、单 Agent、锁步运行的纵向切片。这里缩小的是每项能力
的深度，不是从产品闭环中删除节点。

只有同一场运行能够同时被管理控制台和 Godot 看见，并由独立 checker 根据公开证据分类后，
本版本才算完成。

## Package 0.13.0：WorldEngine 可运行锚点

Package name：`0.13.0-worldengine-runnable-anchor`

状态：closed / WorldEngine 侧锚点已验证

类型：mixed implementation package

收口说明：本 package 自有验收项已通过当前聚焦、E2E、黑盒、浏览器和 evaluator gate。由于
无关的脏 legacy 断言，全后端回归仍为 `484 passed, 1 failed`；本 package 不声明全仓全部
通过或完整 v0.13 PASS。

目标：在通用、版本化客户端协议后面，实现 WorldEngine 侧最小可运行闭环和管理控制台。

存在原因：在生成、Session boot、锁步运行、Agent 动作、干预判定、状态证据和投影共享同一场
正典运行之前，外部客户端无法验证一个连贯世界。

输入 / 必读材料：

- v0.13 parent documents。
- `docs/living-world-development-flow.zh.md`。
- Project North Star、product model、scope boundaries 和 iteration rules。
- 只有实现开始后才读取当前代码，并把它当成可复用资产清单，而不是设计权威。

允许修改：

- 在 active `backend/app/` 路径中新增版本化通用 HTTP schema 和 capability manifest。
- 使用固定 seed 的确定性结构化世界包生成。
- Session boot、lockstep step/run、规则、事件、diff、快照、公开投影和 evidence export。
- 最小 public Agent perception/decision/action/result 链和有界公开 experience link。
- 带明确窗口的用户干预：一次被接受的 bounded direction，一次被拒绝的直接事实修改。
- `frontend/` 下工作型管理控制台；它使用同一组 API，绝不直接写 storage。
- 聚焦 backend、frontend 和 E2E tests。

禁止修改：

- WorldEngine 中不放具体锚点世界内容。
- 不要求 live provider、WebSocket、生产数据库、部署或 Godot project，也不修改外部仓库。
- 不暴露 raw thought、private memory、provider traces，也不允许客户端提交正典 patch。
- 不在 `backend/worldengine/` 下实现。

预期交付物：

- `CapabilityManifest` 和版本化 control/runtime/evidence API。
- 带 `package_hash` 的确定性 `RunnableWorldPackage`。
- 带单调 `tick`、`revision` 和 `state_hash` 的 Session state。
- 与规则关联的 Agent action 和用户干预证据。
- 覆盖完整 WorldEngine 侧流程的管理控制台。
- 聚焦测试和当前 review evidence。

预期测试 / 验证：

- 确定性 package hash tests。
- Session source-package 和 state-hash consistency tests。
- 精确 lockstep tick count tests。
- Agent 因果链和第二次决策 experience-link tests。
- 同一个明确窗口里的 accepted/rejected intervention tests。
- 只知道 base URL 和 manifest 的通用协议黑盒测试。
- 管理控制台 unit、build 和 focused E2E smoke。

兼容性约束：

- 目标 contract 不从当前 API shape 推导。
- 优先新增版本化公共 surface 和 adapter，而不是静默修改现有响应。
- 不得回滚或覆盖工作区里的既有脏改动。
- 任何复用实现都必须通过新测试，不得削弱 contract。

范围护栏：

- 一个固定 seed 世界包、一个 Session、一个 Agent、一个有意义状态变量、一条规则动作和两次
  干预已经足够。
- 具体世界只存在于外部仓库。
- `0.13.0` 不得声明完整 MVP PASS，因为 Godot 和外部 checker 证据属于后续 package。

退出条件：

- Documentation/contract evaluator 无 P1/P2 finding。
- 用户只为本 package 授权实现。
- 聚焦 backend/frontend/E2E 检查有当前通过证据。
- 通用黑盒客户端可以完成 WorldEngine 侧流程。
- Package review 无未解决 P1/P2，并把稳定 contract bundle 交给 `0.13.1`。

交给下一包：发布版本化 manifest、schema、example requests 和 evidence contract，但不把具体外部
fixture 复制进 WorldEngine。

## Package 0.13.1：Godot 验证客户端锚点

Package name：`0.13.1-godot-validation-client-anchor`

状态：planned / documentation preparation only

类型：mixed external-repository package

当前授权仅包含文档准备。完整外部 milestone 完成评审并获得明确批准前，实现、外部仓库修改、
Godot/checker 运行和证据执行均未授权。

目标：把 `WorldEngine-Validation-Client` 调整为最小 Godot 2D 场景 executor，加一个可独立
运行的 checker。

存在原因：Headless API 和 Web 管理控制台不能证明游戏引擎能够消费通用契约、维持投影一致性、
回传类型化反馈并产生独立证据。

输入 / 必读材料：

- 已评审 `0.13.0` public manifest/schema/evidence bundle。
- 外部仓库 `AGENTS.md` 和 active milestone rules。
- 经过 v0.13 重新核对、仍然兼容的历史 scenario/evidence/checker 文档资产。

允许修改：

- 在外部仓库内部创建 Godot project/package。
- 在外部存放一个具体固定 seed 锚点世界和视觉映射。
- 新增只通过 public manifest 和 HTTP protocol 连接的 scenario runner。
- 新增独立 checker package/process，消费 evidence export 和 Godot operation records。
- 把旧 Web UI/API 实现冻结为 legacy，只迁移经过评审的 scenario、evidence 和 result-contract
  资产。
- 使用隔离的 run layout：executor 只能写 `raw/`，封存后的 artifact manifest 记录 hashes，
  只有 checker 可以写 `verdict/`。

禁止修改：

- 本外部 package 不修改 WorldEngine。
- 不直接访问数据库，不 import 内部 Python 代码，不提交正典 patch，不拥有 provider call，
  不读取 private memory/raw thought，executor 不得自证通过。
- Checker 不得重新解释 canonical world facts 或 event legality；它只判断公开证据是否支持
  suite assertions。
- 不做逐帧 WorldEngine 同步、精美游戏，也不全面重写所有旧 milestone。

预期交付物：

- 最小 Godot 2D executor。
- 外部锚点场景和 projection mapping。
- 带 request ID、session/tick/revision/state hash 的 operation log，以及必要的截图或 frame
  evidence。
- 独立 checker 和 result-directory contract。
- Checker 生成的 `run_id`/nonce、clean-run directory、`seal.json`、完整 public-response
  hashes 和 negative mutation fixtures。
- 外部仓库 tests 和 review evidence。

预期测试 / 验证：

- Godot project 能启动并渲染非空场景。
- Executor 只从 public manifest 发现 WorldEngine。
- Dashboard 与 Godot 报告同一 session/revision/state hash 和两次干预结果。
- Godot 至少提交一次类型化 action 或 feedback request。
- Checker 会拒绝缺失、不一致、自我声明或过期证据。
- Checker 会拒绝篡改 hash、复用 run ID、tick 非单调、session ID 串线、敏感输出和预写
  PASS result。

兼容性约束：

- 第一阶段迁移期间，旧 Web/API code 可以保持冻结。
- 历史 result directory 标记为非当前，不能满足 v0.13。
- Executor 和 checker 可以共享 schema file，但不能共享执行状态或 success flag。
- 外部 milestone 必须在实现授权前修复既有 v0.9.1 README/review 状态不一致。

范围护栏：

- 一个 2D scene、一个 Agent projection、一个有意义 object/state 和基本操作已经足够。
- v0.13 不新增第三个仓库。
- 外部场景不得反过来成为 core abstraction 来源。

退出条件：

- 实现前完成外部 milestone 文档评审。
- Godot 和 checker 作为独立 package/process 运行。
- 外部 focused tests 通过，且无 P1/P2 finding。
- 可以向 `0.13.2` 交付 result candidate，但不能提前声明 PASS。

交给下一包：提供全新的 operation/evidence directory，包含所有关联 ID，且不预填 final
classification。

## Package 0.13.2：锚点运行验证与收口

Package name：`0.13.2-anchor-run-validation-and-closeout`

状态：planned / documentation package required

类型：validation and closeout package

目标：从干净状态执行完整锚点运行，并根据当前公开证据对最小可运行 MVP 分类。

存在原因：组件测试通过或 Godot 场景启动，并不能证明生成、运行、Agent 行为、用户干预、投影
和验证形成了同一条因果世界历史。

输入 / 必读材料：

- `0.13.0` 和 `0.13.1` 已评审 closeout evidence。
- 当前 WorldEngine 与外部验证仓库 revision。
- Anchor scenario assertion matrix 和 result-directory contract。

允许修改：

- 只有建立了独立已评审 child package，才允许 validation-only repair。
- Clean-run scripts、evidence capture、checker execution 和 closeout docs。
- 自动证据采集后的人工视觉 checkpoint。

禁止修改：

- 不在 closeout 中隐藏实现修复。
- 不复用 v0.10-v0.12 或更早的外部 result directory。
- 不把 `FAIL`/`BLOCKED` 人工改写为 `PASS`。
- Private state 或纯 UI 证据不得成为权威结果。

预期交付物：

- Clean-run environment 与 revision manifest。
- WorldEngine evidence bundle。
- Godot operation 和 visual evidence。
- 带 evidence refs 的逐 assertion checker report。
- 最终 `PASS`、`PARTIAL`、`BLOCKED` 或 `FAIL` closeout。

预期测试 / 验证：

- 生成固定 seed package 并验证 `package_hash` handoff。
- 运行精确 bounded ticks 并验证状态单调性。
- 验证 Agent 因果链和引用先前经历的第二次决策。
- 在同一个 open window 内提交 accepted 和 rejected intervention。
- 对比 Dashboard 与 Godot 的 session/revision/state hash。
- 用篡改或缺失 evidence 运行 checker negative controls。

兼容性约束：

- 结果只适用于记录的 WorldEngine 和外部仓库 revision。
- `BLOCKED` 只用于必需依赖导致无法执行；已经执行但行为或证据不符时是 `FAIL`。
- 缺失证据永远不能变成 PASS。

范围护栏：

- Closeout 只验证最小锚点场景。
- 锚点 contract 之外的问题进入后续 roadmap。
- 禁止宣称 polished product 或 general intelligence。

退出条件：

- 每条 assertion 都有状态和 evidence refs。
- Negative controls 证明 checker 能让坏证据失败。
- 人工 checkpoint 确认 Godot 投影连贯，但人工观察不成为权威 oracle。
- 两个仓库都记录 final classification 和 unresolved findings。

交给下一步：若 PASS，则通过新的已评审版本深化世界质量、Agent 连续性、更多客户端或持久化；
若为 `PARTIAL`、`BLOCKED` 或 `FAIL`，则把具体原因路由到新的 scoped repair package。

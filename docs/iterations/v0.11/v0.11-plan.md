# v0.11 Plan

Chinese mirror: `v0.11-plan.zh.md`.

Status: closeout complete / scoped PASS

## Version Name

MVP Rule-Bound World Evolution

## Objective

Make a runnable MVP session evolve through public rules, parameters, user
direction boundaries, legal events, public diffs, and fidelity evidence that
WorldEngine-Validation-Client can inspect.

## Planning Authority Boundary

This file is the v0.11 parent roadmap and planned package specification. The
`0.11.x` sections below are route-map specs only. They do not authorize code,
schema, API, frontend, checker, fixture, provider, evidence execution, or
Validation Client implementation.

Before any `0.11.x` child starts, the agent must create or confirm that
child's complete document set, then pass its review gate.

## Version Boundaries

v0.11 may define or implement after reviewed child authorization:

- provider and worldview generation preflight for world creation/evolution.
- public structured rules, parameters, constraints, and legality references.
- user direction queue and boundary enforcement.
- event candidate generation/evaluation/apply path.
- public diff/replay evidence.
- worldview fidelity checks before and after bounded runtime.

v0.11 must not implement:

- complete Agent autonomy or sleep consolidation.
- full external autonomous validation.
- Validation Client code.
- direct user-imposed final facts.
- player item drops, direct detailed event triggering, or
  player-as-world-entity gameplay.
- concrete world fixtures or product-specific backend behavior.

### 0.11.2 Structured World Rules And Parameters

Type: mixed implementation package

Goal: Ensure MVP worlds have structured public parameters, rules,
constraints, and boundaries that runtime and validators can inspect.

Allowed changes: additive rule/parameter schemas, validation helpers, session
rule attachment, public summaries, focused tests, and evidence artifacts.

Forbidden changes: no breaking existing params API, no concrete
application-specific resources, no hidden rule engine, no private provider
trace storage.

Expected deliverables: structured rules and params attached to a session,
validation diagnostics, public rule summaries, and client-readable evidence.

Expected tests / verification: schema tests, invalid-rule rejection tests,
runtime compatibility tests, redaction tests, and manifest/evidence checks.

Compatibility constraints: existing `/world/params` behavior remains
additive-compatible.

Scope guardrails: stop if rules cannot be referenced by event legality or
diff evidence.

Exit criteria: a session exposes rules and params that can be validated and
referenced by later event generation.

Handoff to next package:
`0.11.3-natural-language-direction-queue-and-boundary`.

redaction, replay evidence, and client status classification.

Compatibility constraints: existing director-guidance endpoints remain
compatible or are wrapped additively.

### 0.11.5 Worldview Fidelity And v0.11 Validation

Package name: `0.11.5-worldview-fidelity-and-v0.11-validation`

Type: mixed validation package

Goal: Validate that generated world rules and bounded runtime behavior remain
faithful to the user's basic worldview.

added, targeted E2E if UI changed, `git diff --check`, and redaction scans.

Compatibility constraints: v0.11 validation must not claim Agent autonomy or
complete MVP automation.

Scope guardrails: stop if fidelity depends on raw prompt/response or hidden
private evaluation.

Exit criteria: v0.11 can honestly be reported as `rule-bound world evolution
PASS`, `PARTIAL`, `BLOCKED`, or `FAIL` with evidence.

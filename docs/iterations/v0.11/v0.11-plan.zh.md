# v0.11 Plan

英文版本：`v0.11-plan.md`。

状态：`closeout complete / scoped PASS`

## Version Name

MVP 规则约束下的世界演化

## 目标

让 runnable MVP session 通过 public rules、parameters、user direction boundaries、
legal events、public diffs 和 fidelity evidence 演化，并且这些证据能被
WorldEngine-Validation-Client 检查。

## 规划权限边界

本文件是 v0.11 parent roadmap 和 planned package specification。下面的 `0.11.x`
只是路线规格，不授权 code、schema、API、frontend、checker、fixture、provider、
evidence execution 或 Validation Client implementation。

任何 `0.11.x` 子包开始前，都必须先创建或确认该子包完整文档集，并通过 review gate。

## Version Boundaries

v0.11 在子包评审后可以定义或实现：

- 面向 world creation/evolution 的 provider 和 worldview generation preflight。
- public structured rules、parameters、constraints 和 legality references。
- user direction queue 和 boundary enforcement。
- event candidate generation/evaluation/apply path。
- public diff/replay evidence。
- bounded runtime 前后的 worldview fidelity checks。

v0.11 不实现：

- 完整 Agent autonomy 或 sleep consolidation。
- 完整 external autonomous validation。
- Validation Client code。
- 用户直接指定 final fact。
- 玩家投放物品、直接触发细节事件或 player-as-world-entity gameplay。
- concrete world fixtures 或 product-specific backend behavior。

### 0.11.1 Provider And Worldview Generation Preflight

Package name: `0.11.1-provider-and-worldview-generation-preflight`

Status: implementation complete / focused verification passed

Type: mixed implementation package

Goal: 为 MVP world creation 和 evolution 增加诚实的 provider/worldview preflight semantics。

Why this exists: MVP 必须知道自己是在 provider-backed generation、safe mock、
deterministic fallback，还是 blocked provider state。

Inputs / required reading: v0.10 session creation、v0.9 provider 和 worldview
generation packages、provider redaction rules、当前 `/provider/live-smoke`、manifest
debug handoff contract。

Allowed changes: provider preflight API 或 command、redacted provider summary、
worldview generation mode labeling、blocked/fallback/pass taxonomy、focused tests、
manifest/evidence updates。

Forbidden changes: 不记录 raw prompt/response，不暴露 secret，不让 Validation Client 调用
provider，不把 silent fallback 当 PASS，不加 concrete world content。

Expected deliverables: provider preflight result、worldview generation preflight
summary、redaction-safe evidence 和 client-discoverable status。

Expected tests / verification: backend provider/preflight tests、redaction tests、
manifest compatibility tests；只有 provider environment 和 child authorization 允许时才跑 optional live smoke。

Compatibility constraints: provider unconfigured state 必须保持安全，并分类为 blocked/not_configured，
而不是崩溃式失败。

Scope guardrails: 如果 provider work 需要暴露 key material 或 raw provider traces，必须停止。

Exit criteria: MVP world creation 可以诚实标记 provider-backed、safe-mock、deterministic
fallback 或 blocked mode。

Handoff to next package: `0.11.2-structured-world-rules-and-parameters`。

### 0.11.2 Structured World Rules And Parameters

Package name: `0.11.2-structured-world-rules-and-parameters`

Status: implementation complete / focused verification passed

Type: mixed implementation package

Goal: 确保 MVP worlds 拥有 runtime 和 validators 可检查的 structured public parameters、
rules、constraints 和 boundaries。

Why this exists: 如果 rules 只是自由文本或隐藏 model output，世界就无法以可测试方式演化。

Inputs / required reading: v0.10 session model、v0.11 preflight、v0.9 rule schema work、
现有 world params 和 event legality helpers。

Allowed changes: additive rule/parameter schemas、validation helpers、session rule
attachment、public summaries、focused tests 和 evidence artifacts。

Forbidden changes: 不破坏 existing params API，不加 concrete application-specific resources，
不做 hidden rule engine，不存 private provider trace。

Expected deliverables: attached to session 的 structured rules 和 params、validation diagnostics、
public rule summaries 和 client-readable evidence。

Expected tests / verification: schema tests、invalid-rule rejection tests、runtime
compatibility tests、redaction tests、manifest/evidence checks。

Compatibility constraints: 现有 `/world/params` behavior 保持 additive-compatible。

Scope guardrails: 如果 rules 不能被 event legality 或 diff evidence 引用，必须停止。

Exit criteria: session 暴露可验证、可被后续 event generation 引用的 rules 和 params。

Handoff to next package:
`0.11.3-natural-language-direction-queue-and-boundary`。

### 0.11.3 Natural-Language Direction Queue And Boundary

Package name: `0.11.3-natural-language-direction-queue-and-boundary`

Status: implementation complete / focused verification passed

Type: mixed implementation package

Goal: 允许用户用自然语言引导世界演化，但不能直接施加 final facts 或 Agent private-state changes。

Why this exists: 用户 guidance 是 MVP 的一部分，但必须作为 engine 通过 rules 处理的
world-level influence。

Inputs / required reading: v0.10 session APIs、v0.11 rules、v0.9 direction boundary
work、event legality rules、redaction rules、Validation Client operation-log expectations。

Allowed changes: session-scoped direction queue、classifier/boundary checks、public
direction summaries、event-candidate influence fields、focused tests 和 evidence artifacts。

Forbidden changes: 不允许 direct death/injury/inventory/relationship outcomes，不允许玩家投放物品，
不允许直接触发细节事件，不直接修改 Agent private memory 或 goal，不绕过 rules、location、time、
probability 或 state。

Expected deliverables: direction queue API、boundary diagnostics、accepted/rejected
guidance evidence、replayable operation records，以及 public examples：`kill this Agent now`
被拒绝，`lightning-strike risk may affect this Agent` 只能保留为 external pressure。

Expected tests / verification: tests 覆盖 accepted guidance、rejected final facts、
lightning-risk-as-pressure handling、private Agent-state attempts、redaction、replay evidence
和 client status classification。

Compatibility constraints: 现有 director-guidance endpoints 保持兼容，或通过 additive wrapper 兼容。

Scope guardrails: 如果 guidance 变成 direct mutation，而不是 queued world-level pressure，必须停止。

Exit criteria: user guidance 可以入队，并在后续 rule-bound event generation 中被考虑，同时不违反边界。

Handoff to next package:
`0.11.4-rule-compliant-event-generation-and-diffs`。

### 0.11.4 Rule-Compliant Event Generation And Diffs

Package name: `0.11.4-rule-compliant-event-generation-and-diffs`

Status: implementation complete / focused verification passed

Type: mixed implementation package

Goal: 在 bounded runtime 中生成或选择 external/world events，并应用与 rules、parameters
和 direction influence 关联的合法 public diffs。

Why this exists: MVP 世界必须通过可检查原因变化，而不是固定 counter 或用户直接 mutation。

Inputs / required reading: v0.11 rules、direction queue、当前 event legality evaluator、
runtime step/run controls、event log、snapshot/diff evidence 和 checker handoff contract。

Allowed changes: event candidate generator、legality evaluate/apply path、public diff
records、指向 rules/direction/params 的 event refs、focused tests 和 evidence artifacts。

Forbidden changes: 不做 hidden random oracle，不产生 illegal final outcomes，不修改 private Agent，
不做 unbounded provider calls，不在 core fixtures 中放 concrete demo-story events。

Expected deliverables: rule-linked events、accepted/rejected legality evidence、diffs、
replay summaries 和 client-readable event explanations。

Expected tests / verification: backend tests 覆盖 legal/illegal candidates、direction-influenced
candidates、必须继续通过 rules/state/probability 的 lightning-risk examples、diff application、
replay summaries、redaction 和 runtime compatibility。

Compatibility constraints: event log 和 snapshot outputs 保持 additive-compatible。

Scope guardrails: 如果 events 无法解释哪些 public rules 或 state 让它合法，必须停止。

Exit criteria: bounded runtime 可以产生 rule-compliant events 和 public diffs，external
validators 可检查。

Handoff to next package:
`0.11.5-worldview-fidelity-and-v0.11-validation`。

### 0.11.5 Worldview Fidelity And v0.11 Validation

Package name: `0.11.5-worldview-fidelity-and-v0.11-validation`

Status: review complete / scoped verification passed

Type: mixed validation package

Goal: 验证生成的 world rules 和 bounded runtime behavior 是否仍忠实于用户基础世界观。

Why this exists: 世界可能初看结构完整，但运行后偏离 premise。MVP validation 需要 immediate
和 run-based fidelity。

Inputs / required reading: 所有 v0.11 child reviews、public generation summary、rules/params、
direction evidence、event/diff evidence、snapshots 和 Validation Client handoff fields。

Allowed changes: fidelity scorecard、validation docs、如批准则更新 checker fixtures、result
summaries 和 closeout status synchronization。

Forbidden changes: 没有 checker/scorecard evidence 不做 subjective PASS，不泄露 private
evaluator data，不做新功能 scope，除非 package 明确记录 blocker repair。

Expected deliverables: immediate fidelity summary、bounded-run fidelity summary、v0.11
validation result 和 handoff to v0.12。

Expected tests / verification: focused backend tests、如新增则 checker/schema tests、
UI 改动时 targeted E2E、`git diff --check` 和 redaction scans。

Compatibility constraints: v0.11 validation 不声明 Agent autonomy 或 complete MVP automation。

Scope guardrails: 如果 fidelity 依赖 raw prompt/response 或 hidden private evaluation，必须停止。

Exit criteria: v0.11 可以有证据地报告为 `rule-bound world evolution PASS`、`PARTIAL`、
`BLOCKED` 或 `FAIL`。

Handoff to next package: v0.12 parent campaign。

# v0.12 Plan

Chinese mirror: `v0.12-plan.zh.md`.

Status: closeout complete / PARTIAL

## Version Name

MVP Agent Continuity And Validation Automation

## Objective

Complete the MVP by adding a minimal public Agent continuity loop and a
checker-backed external validation path through WorldEngine-Validation-Client.

## Planning Authority Boundary

This file is the v0.12 parent roadmap and planned package specification. The
`0.12.x` sections below are route-map specs only. They do not authorize code,
schema, API, frontend, checker, fixture, provider, evidence execution, or
Validation Client implementation.

Before any `0.12.x` child starts, the agent must create or confirm that
child's complete document set, then pass its review gate.

## Version Boundaries

v0.12 may define or implement after reviewed child authorization:

- public Agent state and runtime loop integration.
- observable intent, no-intent, action, wait, rest, and sleep states.
- public memory/consolidation summaries without private internals.
- read-only novel-style narrative and diagnostic inspection surfaces.
- MVP evidence artifacts and scorecards.
- Validation Client handoff contract and autonomous validation result schema.
- terminology separating in-world Agents from external validation agents.

v0.12 must not implement:

- real-consciousness claims.
- raw/private Agent internals in evidence.
- client-owned Agent autonomy.
- Validation Client code inside WorldEngine.
- external validation agents represented as in-world Agents.
- concrete game content.

### 0.12.1 Agent Public State And Runtime Loop

Package name: `0.12.1-agent-public-state-and-runtime-loop`

Status: implementation complete / focused verification passed

Type: mixed implementation package

Goal: Add a minimal public Agent state and runtime-integrated loop that can
observe, decide action or no-action, execute, and react to events.

Why this exists: The MVP needs visible Agent life evidence, not just one
client-invoked parameter action or a default noop.

Inputs / required reading: v0.11 rule/event evidence, existing Agent loop,
perception, action adapter, memory context, session runtime, event log, and
redaction rules.

Allowed changes: session Agent records, public state schema, runtime loop hook,
intent/no-intent/action/wait/rest states, action result events, focused tests,
and evidence summaries.

Forbidden changes: no raw thought, no private goals, no client-scripted action
reported as autonomy, no direct bypass of rule/event legality, no full
personality simulation.

Expected deliverables: public Agent state API/artifact, runtime loop
integration, event reactions, and tests proving actions originate from
WorldEngine.

Expected tests / verification: backend tests for observe/no-intent/action,
event reaction, client-scripted-action rejection, redaction, and runtime
compatibility.

Compatibility constraints: existing request-driven Agent loop remains
compatible or is wrapped additively.

Scope guardrails: stop if Agent action is controlled by the client instead of
WorldEngine public runtime state.

Exit criteria: at least one Agent can produce public observe/intent-or-no-intent/action-or-wait
evidence during bounded runtime.

### 0.12.2 Agent Memory And Rest Consolidation MVP

Package name: `0.12.2-agent-memory-and-rest-consolidation-mvp`

Type: mixed implementation package

artifacts, and focused tests.

Forbidden changes: no raw private memory payloads, no raw thought, no
automatic per-tick long-term memory/personality/skill mutation, no diagnostic

Expected deliverables: public memory summaries, rest/sleep records,
consolidation artifacts, and redaction-safe evidence.

Expected tests / verification: backend tests for memory summary creation,
multi-tick rest/sleep consolidation, redaction, no per-tick mutation
guarantees, and evidence refs.

Compatibility constraints: existing memory APIs remain additive-compatible.

Scope guardrails: stop if evidence cannot distinguish short-term summaries,
long-term summaries, and consolidation records.

Exit criteria: an Agent can carry public memory across ticks and consolidate
through rest/sleep evidence.

### 0.12.3 Narrative And Diagnostic Inspection Surfaces

Package name: `0.12.3-narrative-and-diagnostic-inspection-surfaces`

Status: review complete

Type: mixed implementation package

Goal: Provide lightweight read-only novel-style narrative projection and
out-of-world diagnostic Agent conversation surfaces for inspecting MVP
behavior.

Why this exists: Humans need readable ways to judge whether the world is
running sensibly, but these surfaces must not mutate canonical state.

Inputs / required reading: v0.11 event/diff evidence, v0.12 Agent summaries,
existing narrative/diagnostic boundary work, redaction rules, and projection
contracts.

Allowed changes: read-only projection APIs/artifacts, session/tick-range/
branch/Agent-focused narrative query fields, diagnostic dialogue evaluation
summaries, provenance fields, frontend or manifest discovery if approved,
focused tests.

Forbidden changes: no narrative mutation of world state, no diagnostic
conversation insertion into world timeline or Agent memory, no raw thought,
private memory, or provider traces.

Expected deliverables: novel-style narrative projection summary, diagnostic
conversation summary, user-facing query parameters, provenance/redaction
fields, and client-readable artifacts.

Expected tests / verification: backend tests for session/tick-range/branch/
Agent-focused projection queries, diagnostic Q&A from public evidence,
read-only behavior, redaction, provenance, mutation rejection, and
compatibility with event/Agent evidence.

Compatibility constraints: canonical world state, timeline, and Agent memory
must remain unchanged by projection/diagnostic inspection.

Scope guardrails: stop if these surfaces become gameplay dialogue, canonical
story mutation, an implicit record of a player inside the world, or a hidden
way to steer world evolution outside the direction queue.

Exit criteria: a human or validator can inspect world/Agent behavior through
readable projections without changing the world.

`0.12.4-validation-client-mvp-evidence-handoff`.

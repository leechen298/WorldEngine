## Goal

Add a minimal session-scoped public Agent state and runtime-integrated loop
that can observe the public session, choose action or no-action, execute only
WorldEngine-owned public behavior, and record public evidence.

This package must not treat a client-submitted action as Agent autonomy. The
Agent step request may select a session and Agent, but the resulting
observe/intent/action-or-wait/rest evidence must be generated by WorldEngine
from public runtime/session state.

## Scope

Allowed after review approval:

- Add public Agent state schemas for session-scoped Agent status.
- Add an in-memory session Agent store or attach Agent state to the existing
  session store.
- Add session Agent read/list/step APIs under `/sessions/{session_id}/agents`.
- Add a deterministic minimal Agent loop that chooses one of:
  `observe`, `no_intent`, `action`, `wait`, or `rest`.
- Record public Agent evidence events such as `world.agent.observed`,
  `world.agent.intent.recorded`, `world.agent.action.recorded`, or
  `world.agent.rest.recorded`.
- Update manifest/public handoff discovery fields.
- Add focused backend tests for state, loop, client-scripted-action rejection,
  redaction, event evidence, and compatibility.

Forbidden:

- No raw thought, chain-of-thought, private memory, private goals, secrets,
  raw prompts, raw provider responses, provider traces, or hidden context in
  evidence.
- No client-submitted action intent represented as autonomous Agent behavior.
- No direct bypass of v0.11 rule/event legality.
- No full personality simulation, long-term memory consolidation, sleep
  implementation, narrative projection, diagnostic conversation, checker
  automation, provider live call, external Validation Client automation, or
  complete MVP PASS claim.
- No concrete demo-world seed data or product-specific backend behavior.
- No implementation under `backend/worldengine/`.

## Deliverables

- Public session Agent state schema and response artifacts.
- Session-scoped Agent list/read/step API.
- Runtime-linked Agent step evidence with event IDs and runtime refs.
- Client-scripted-action rejection or omission evidence.
- Manifest/public handoff updates.
- Focused backend tests and review evidence.

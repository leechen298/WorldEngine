# v0.10 Plan

英文版本：`v0.10-plan.md`。

状态：`closeout PASS / handed off to v0.11`

## Version Name

MVP 调试契约与可运行世界会话

## 目标

建立第一条 MVP 纵向链路：WorldEngine-Validation-Client 可以连接、发现 public MVP
surfaces，并导出诚实的 checker handoff；然后用户输入基础世界观后，可以创建 world
session，用有限 runtime controls 推进它，查看 events 和 snapshots。

## 规划权限边界

本文件是 v0.10 parent roadmap 和 planned package specification。下面的 `0.10.x`
只是路线规格，不授权 code、schema、API、frontend、checker、fixture、provider、
evidence execution 或 Validation Client implementation。

任何 `0.10.x` 子包开始前，都必须先创建或确认该子包完整文档集，并通过 review gate。

## Version Boundaries

v0.10 在子包评审后可以定义或实现：

- public world session contracts。
- MVP manifest/version/debug handoff contract。
- session-scoped runtime state 和 in-memory storage。
- worldview input 到 runnable session creation。
- 带明确标签的 deterministic/mock fallback。
- bounded run controls 和 session snapshots。
- create/run/inspect 的 dashboard flow。
- 供 external client discovery 使用的 MVP manifest fields。
- 用于 debugging 的 replay/worldline branch labels，并使用类似代码分支的 branch terminology，
  不使用 parent/source-world wording。

v0.10 不实现：

- 完整 Agent autonomy。
- 超过必要 stub/reference 的类脑记忆沉淀。
- 完整 rule-compliant autonomous event generation loop。
- Validation Client code。
- 精美游戏表现或发行。
- 没有 live evidence 的 live provider quality claim。
- player-as-world-entity gameplay、投放物品或直接触发细节事件。
- parent/child/source-world branch semantics。

### 0.10.1 MVP Public Manifest And Debug Handoff

redaction summary shape、focused backend tests 和 docs。

Forbidden changes: 不改 Validation Client code，不执行 provider call，不实现 runtime session，
不生成 world data，不记录 raw prompts、secrets、private Agent memory 或 private evaluator data。

surface list、避免 parent/source-world semantics 的 branch/replay terminology、minimal
handoff artifact skeleton，以及证明 blocked/not_run statuses 是合法输出的测试。

Expected tests / verification: focused manifest/API tests、redaction checks、schema/status
tests，以及 existing manifest consumers compatibility check。

Compatibility constraints: 现有 manifest fields 必须保持 additive-compatible；legacy v0.8/v0.9
fields 不得误报 MVP PASS。

Scope guardrails: 如果 package 开始实现 client behavior，或把 UI smoke 当成 WorldEngine
validation，必须停止。

Exit criteria: WorldEngine-Validation-Client 可以发现 MVP surfaces，并在不拥有 provider
或 evaluator logic 的情况下导出 checker-accepted `blocked` 或 basic handoff。

Handoff to next package: `0.10.2-world-session-contract-and-state-store`。

### 0.10.4 Bounded Session Runtime And Snapshot Evidence

Package name: `0.10.4-bounded-session-runtime-and-snapshot-evidence`

Status: implementation complete / focused verification passed

Type: mixed implementation package

Goal: 让 session runtime execution 有边界、可控制，并由 events、diffs、snapshots 提供证据。

Why this exists: MVP 必须允许用户或 external client 运行 1 tick、运行 N ticks、暂停、继续，
并能检查发生了什么变化，而不是无限运行。

Inputs / required reading: runtime engine、archive/snapshot stores、event log、
v0.9 bounded runtime package、session store 和 Validation Client evidence handoff fields。

Allowed changes: session-scoped run controls、run summary payloads、snapshot interval
handling、diff summary artifacts、public run budget fields、focused backend tests 和
compatibility docs。

Forbidden changes: 不做 infinite default run，不在没有 guard fields 的情况下执行 provider-cost
行为，不记录 secret/raw provider evidence，除非子包授权不做 durable persistence。

Expected deliverables: run one tick、run N ticks、pause、resume、session snapshot list、
run summaries、diff/replay summary shape，以及不会暗示 parent/child world hierarchy 的
branch-ready timeline evidence labels。

Expected tests / verification: backend tests 覆盖 bounded run、pause/resume、snapshot
generation、event grouping、budget guards 和现有 runtime compatibility。

Compatibility constraints: 现有 runtime endpoints 必须继续工作，或通过 additive wrapper 明确兼容。

Scope guardrails: 如果 runtime controls 绕过 session state，产生不能 replay/export 的 evidence，
或把 replay branches 描述成 parent/source worlds，必须停止。

Exit criteria: clients 可以通过 bounded runtime operations 驱动 session，并获取 public change evidence。

Handoff to next package: `0.10.5-dashboard-mvp-session-flow`。
Current handoff state: complete；`0.10.5` documentation package is needed before
implementation。

# v0.10 Plan

Chinese mirror: `v0.10-plan.zh.md`.

Status: closeout PASS / handed off to v0.11

## Version Name

MVP Debug Contract And Runnable World Session

## Objective

Build the first MVP vertical slice where WorldEngine-Validation-Client can
connect, discover public MVP surfaces, and export an honest checker handoff,
then a user can create a world session from a basic worldview, run it with
bounded controls, and inspect events and snapshots.

## Planning Authority Boundary

This file is the v0.10 parent roadmap and planned package specification. The
`0.10.x` sections below are route-map specs only. They do not authorize code,
schema, API, frontend, checker, fixture, provider, evidence execution, or
Validation Client implementation.

Before any `0.10.x` child starts, the agent must create or confirm that
child's complete document set, then pass its review gate.

## Version Boundaries

v0.10 may define or implement after reviewed child authorization:

- public world session contracts.
- MVP manifest/version/debug handoff contract.
- session-scoped runtime state and in-memory storage.
- worldview input to runnable session creation.
- deterministic/mock fallback with explicit labeling.
- bounded run controls and session snapshots.
- dashboard flow for create/run/inspect.
- MVP manifest fields for external client discovery.
- replay/worldline branch labels for debugging, with code-branch-like branch
  terminology and no parent/source-world wording.

v0.10 must not implement:

- complete Agent autonomy.
- brain-inspired memory consolidation beyond required stubs and references.
- rule-compliant autonomous event generation as a full loop.
- Validation Client code.
- polished game presentation or distribution.
- live provider quality claims without live evidence.
- player-as-world-entity gameplay, item drops, or direct detailed event
  triggering.
- parent/child/source-world branch semantics.

### 0.10.4 Bounded Session Runtime And Snapshot Evidence

Package name: `0.10.4-bounded-session-runtime-and-snapshot-evidence`

Status: implementation complete / focused verification passed

Type: mixed implementation package

Goal: Make session runtime execution bounded, controllable, and evidenced by
events, diffs, and snapshots.

Why this exists: MVP must let a user or external client run one tick, run N
ticks, pause, resume, and inspect what changed without unbounded execution.

Inputs / required reading: runtime engine, archive/snapshot stores, event log,
v0.9 bounded runtime package, session store, and Validation Client evidence
handoff fields.

Allowed changes: session-scoped run controls, run summary payloads,
snapshot interval handling, diff summary artifacts, public run budget fields,
focused backend tests, and compatibility docs.

Forbidden changes: no infinite default run, no provider-cost execution without
guard fields, no secret/raw provider evidence, no durable persistence unless a
child contract adds it.

Expected deliverables: run one tick, run N ticks, pause, resume, session
snapshot list, run summaries, diff/replay summary shape, and branch-ready
timeline evidence labels that do not imply parent/child world hierarchy.

Expected tests / verification: backend tests for bounded run, pause/resume,
snapshot generation, event grouping, budget guards, and existing runtime
compatibility.

Compatibility constraints: existing runtime endpoints must continue to work or
be explicitly wrapped additively.

Scope guardrails: stop if runtime controls bypass session state, produce
evidence that cannot be replayed/exported, or describe replay branches as
parent/source worlds.

Exit criteria: clients can drive a session through bounded runtime operations
and retrieve public evidence of changes.

Handoff to next package: `0.10.5-dashboard-mvp-session-flow`.

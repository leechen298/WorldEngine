# v0.7 Plan 计划

状态：final / closeout complete

## 版本名称

External Validation Readiness / Projection Consumer Readiness

## 目标

通过 public contracts、redacted reports、consumer-facing projection boundaries、readiness
manifests 和 compatibility evidence，让 WorldEngine 准备好被 external validation suites 与
projection consumers 使用，同时保持 WorldEngine 的 generic recursive world generation/runtime
engine 边界。

v0.7 要把 v0.6 generation 与 runtime evidence 转化为可 review 的 public readiness surfaces。它不能把
private external validation worlds、external application behavior 或 projection-product
implementation 导入 core repository。

## 版本边界

v0.7 可以定义或实现：

- external validation readiness concepts 与 public contract surfaces。
- redacted validation report schema、report validation 和 evidence archive rules。
- 面向 runtime、event、Agent loop、memory-summary 与 generation-readiness payloads 的 projection
  consumer contracts。
- external suites 可消费的 contract bundle 与 readiness manifest export paths。
- 跨 public engine contracts 的 generic quality regression 与 compatibility evidence。
- 只有在 reviewed child packages 授权后，才运行或修改 focused backend、API、frontend、E2E、
  Agent smoke、autonomous saved-result 和 compatibility checks。
- release-candidate、final closeout 与 post-closeout evidence documents。

v0.7 不得实现：

- first external projection application；该范围属于 v0.8。
- 本仓库内的 concrete external validation worlds 或 fixtures。
- concrete world names、maps、characters、locations、resources、story rules、seed data、private
  transcripts、UI selectors、hidden reset APIs 或 private validation oracle behavior。
- application-specific backend logic 或 product packaging flows。
- live provider behavior、generated-world persistence 或 subjective generation-quality approval；这些
  范围需要后续 reviewed version 承担。
- durable persistence 或 migrations，除非 reviewed v0.7 child 明确授权。
- `backend/worldengine/` 下的新 runtime features。
- 没有 current-session evidence 时，不声明 external suite PASS、projection application readiness、
  product readiness 或 full autonomous runner/full-suite PASS。

## 必需兼容基线

任何 implementation-bearing v0.7 child 在修改 runtime、schema、API、event、archive、params、
frontend-facing、test、checker、fixture、migration 或 legacy behavior 前，都必须为 touched surface
提供 current-session evidence，并为相邻 compatibility surfaces 提供 focused regression evidence。

Compatibility-sensitive surfaces 包括：

- `WorldSpec`、`WorldCell`、`EntityRef`。
- `load_worldspec`、`LoadedWorldSpec`、`WorldSpecLoaderResult`、`WorldSpecLoaderError`。
- `RuntimeContext`、`RuntimeContextSummary`、`build_runtime_context`、`summarize_runtime_context`。
- `RuntimeEngine.get_runtime_context`、`RuntimeEngine.step`、tick/time behavior、event emission 与
  runtime-context non-leakage。
- `PerceptionFrame`、`ActionIntent`、`ActionResult`、request-scoped `LoopStep` 和
  `POST /world/agent/loop/step`。
- v0.5 working/episodic memory context surfaces。
- v0.6 world generation request、template、plan、preview、regeneration 和 runtime-readiness surfaces。
- API envelope 与 error shape。
- `/runtime/state`、`/runtime/step`、`/world/events`、`/world/event-steps`、
  `/world/agent/params/propose-and-apply`、`/world/agent/loop/step`、archive behavior 和
  `/world/generation/*`。

Schema 和 API changes 默认必须 additive，除非 active child contract 明确允许 breaking change。

## Codex `/goal` 与 Evaluator Model

`完成 v0.7` 使用 `GOAL_RUNNER.md`、`CURRENT_STATE.md` 和 `CAMPAIGN_PLAN.md`。
Implementation-bearing children 在 closeout 前必须经过 documentation/contract evaluator、
implementation-scope evaluator、code-review evaluator、validation-evidence evaluator 和 closeout
consistency review。

documentation-only children 如果改变 goal routing、evidence rules、package sequencing、
automation-consumption contracts、release status、validation templates、report schemas、projection
contracts 或 mirror obligations，必须使用 read-only documentation evaluator。

如果 evaluator tooling 不可用或未授权，package 必须保持 `planned / ready for review`，或记录 blocker，
不能静默声明 review complete。

Parent roadmap 不创建 active child contracts。未来 child package documents 如果通过 review evidence 发现
parent roadmap 不完整或不安全，可以调整顺序、拆分、合并或 deferred planned packages。

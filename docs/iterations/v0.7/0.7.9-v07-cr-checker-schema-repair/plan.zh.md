# 计划

## 有序执行步骤

1. 创建完整 `0.7.9` 包文档集和中文镜像。
2. 运行文档门禁检查。
3. 派发只读文档 / 契约评估器和镜像 / 范围评估器。
4. 如果 review 通过，更新 `review.md` 为 `implementation_authorized: yes`。
5. 按实现顺序阅读已批准的包文档。
6. 为 V07-CR-01 到 V07-CR-05 添加红灯回归测试。
7. 运行聚焦测试并记录预期红灯失败。
8. 实现最小检查器 / Schema / 模板 / 状态文本修复。
9. 重新运行聚焦和相邻检查器测试。
10. 运行 `test-plan.md` 中的最终 v0.7 验证检查。
11. 派发实现范围、代码审查、验证证据和收尾一致性评估器。
12. 用当前会话证据和最终结论更新 `review.md` 与验证结果文档。

## 阶段边界

- 文档阶段只有在评估器审查通过并记录 `implementation_authorized: yes` 后结束。
- 实现阶段只有在读取已批准包文档后开始。
- 验证结果更新只有在命令证据存在后执行。

## 停止条件

- 必需包文档或镜像缺失。
- 评估器报告 P0/P1 或阻断性 P2。
- 红灯测试未能复现 V07-CR 阻断项。
- 修复需要运行时 / API / 前端 / v0.8 工作。
- 范围守卫发现无关变更或 v0.8 变更进入修复包。
- clean pass 需要不受支持的外部套件、投影就绪、产品就绪、
  live Agent smoke、完整自主运行器或 v0.8 声明。

## 审查更新步骤

`review.md` 必须记录变更文件、已运行命令、红灯 / 绿灯测试证据、
兼容性审查、范围审查、子代理 / 评估器发现、未解决 P1/P2/P3
和最终评估。

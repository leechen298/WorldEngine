# Test Plan

## E2E Tests

Add Playwright E2E coverage for:

- `dashboard-agent-autotune`
- `dashboard-timeline-navigation`

Both must use deterministic Playwright assertions and must not use Codex
narration as PASS evidence.

## Live Agent Smoke Validation

Record a live `dashboard-invalid-param` run under:

```text
test-results/agent-smoke/latest/
```

Required files:

- `result.json`
- `operation-log.jsonl`
- `transcript.md`
- `console.log`
- helper-generated `api-summary.json`
- at least one file under `screenshots/`

`api-summary.json` must be generated by
`tools/testing/agent_smoke_evidence.py collect`, not manually authored.

`result.json.commands` and `operation-log.jsonl` must record helper baseline,
helper collect, and validator commands with `exit_code: 0`.

## Focused Frontend Tests

Run focused frontend tests touched by Auto-Tune or timeline work, such as:

```bash
cd frontend && pnpm test -- WorldPanel.test.ts TimelinePanel.test.ts DashboardPage.test.ts
```

If implementation touches additional frontend modules, include their focused
tests in `review.md`.

## Regression Tests

- Existing E2E scenarios must keep passing.
- Existing Agent smoke validator support must accept the new live
  `dashboard-invalid-param` run.
- Existing frontend unit coverage for WorldPanel, TimelinePanel, and
  DashboardPage must keep passing.
- Existing backend checks must still pass even though backend implementation
  files must not change.

## Commands

Run these after implementation:

```bash
git diff --check
find test-results/agent-smoke/latest -maxdepth 2 -type f | sort
make validate-agent-smoke-result RESULT_DIR=test-results/agent-smoke/latest
make test-e2e
cd frontend && pnpm test -- WorldPanel.test.ts TimelinePanel.test.ts DashboardPage.test.ts
make check-backend
make check-frontend
if git diff --name-only | rg '^(backend/worldengine/|backend/app/)'; then
  echo "Unexpected backend runtime or legacy change"
  exit 1
fi
```

Expected result for the final block: no output.

## Acceptance Criteria

- This package is reviewed before implementation starts.
- `dashboard-agent-autotune` E2E is implemented and passes through
  `make test-e2e`.
- Auto-Tune E2E asserts success, patch details, and params evidence for the
  current MockLLMProvider path.
- `dashboard-timeline-navigation` E2E is implemented and passes through
  `make test-e2e`.
- Timeline E2E asserts page-size behavior, next/previous navigation, row
  expansion, and event type/source/payload detail evidence.
- Live `dashboard-invalid-param` Agent smoke is recorded under
  `test-results/agent-smoke/latest/`.
- Live invalid-param `api-summary.json` is helper-generated and proves
  `system.secret` rejection, unchanged params, and `ui_error_seen: true`.
- `operation-log.jsonl` includes the required invalid-param UI targets and no
  direct API operation records.
- `operation-log.jsonl` and `result.json.commands` include helper baseline,
  helper collect, and validator commands with `exit_code: 0`.
- `make validate-agent-smoke-result
  RESULT_DIR=test-results/agent-smoke/latest` exits `0`.
- Agent smoke docs mark `dashboard-invalid-param` as `live-smoke-recorded`
  only after validation passes.
- Docs clearly state that `test-results/agent-smoke/latest/` now points to the
  invalid-param run and that params-flow live status remains durable in docs.
- Before replacing `test-results/agent-smoke/latest/`, implementation either
  creates a durable `docs/testing/results/` summary for the previous
  params-flow run or records that the 0.1.8 params-flow raw evidence remains
  available through commit `c6da552`.
- Full autonomous, persistence/restart, WorldSpec/WorldCell, and agent
  memory/self gaps remain future-work gaps.
- `review.md` records changed files, commands run, test results,
  compatibility review, scope review, unresolved findings, and final
  assessment.

## Not Run

Do not run in 0.1.9:

- API curl smoke.
- full Codex/test-runner autonomous scenarios.
- autonomous scorecard verdicts.
- persistence/restart tests.
- WorldSpec, WorldCell, recursive world, or world generation tests.
- agent memory or pseudo-self tests.
- v0.2 implementation.

# Contract

## Public Concepts

### Remaining current-code coverage

Remaining current-code coverage means tests for behavior that already exists
in the v0.1 runtime or dashboard. It does not mean adding new runtime
capability.

For 0.1.9, the only remaining current-code coverage items are:

- `dashboard-agent-autotune` E2E.
- `dashboard-timeline-navigation` E2E.
- live `dashboard-invalid-param` Agent smoke evidence.

### Auto-Tune E2E

`dashboard-agent-autotune` is a Playwright E2E scenario for the existing
WorldPanel `LLM Auto-Tune` path backed by `ParamsAgent + MockLLMProvider`.
PASS must come from Playwright assertions, not Codex narration.

### Timeline Navigation E2E

`dashboard-timeline-navigation` is a Playwright E2E scenario for existing
timeline pagination, page-size, row expansion, and expanded event detail
selectors. PASS must come from Playwright assertions.

### Live invalid-param Agent smoke

Live `dashboard-invalid-param` Agent smoke records one real UI/CLI evidence
package for the existing invalid-param dashboard flow. PASS must come from
`make validate-agent-smoke-result`, with `verdict_source:
deterministic_checker`.

## Compatibility Constraints

- Existing runtime behavior must stay compatible.
- Existing API response shapes must stay compatible.
- Existing dashboard user-visible behavior must stay compatible.
- Existing E2E scenarios must keep passing.
- Existing Agent smoke validator behavior must stay compatible.
- `dashboard-params-flow` live smoke history remains valid even if
  `test-results/agent-smoke/latest/` is replaced by the new invalid-param run.

## Allowed Changes

0.1.9 may:

- Modify `frontend/e2e/dashboard.spec.ts` to implement:
  - `dashboard-agent-autotune`
  - `dashboard-timeline-navigation`
- Update focused frontend or E2E tests only if needed to keep the new coverage
  deterministic.
- Create or replace live Agent smoke evidence under
  `test-results/agent-smoke/latest/` for `dashboard-invalid-param`.
- Optionally retain helper input such as `api-baseline.json` in the live run
  directory.
- Update Agent smoke docs and test maps to mark `dashboard-invalid-param` as
  live-smoke-recorded only after validation passes.
- Update E2E scenario docs and test maps to mark `dashboard-agent-autotune` and
  `dashboard-timeline-navigation` as implemented only after `make test-e2e`
  passes.
- Update this package `review.md` with implementation evidence.
- Update v0.1 package indexes and plans for status synchronization.

## Forbidden Changes

- Do not add API curl smoke.
- Do not record direct API calls as Agent operations.
- Do not hand-author live `api-summary.json`.
- Do not change backend runtime behavior.
- Do not change backend API contracts.
- Do not modify `backend/app/`.
- Do not modify `backend/worldengine/`.
- Do not implement full Codex/test-runner autonomous scenarios or scorecards.
- Do not implement persistence/restart tests.
- Do not implement WorldSpec, WorldCell, recursive world, world generation,
  agent memory, or pseudo-self tests.
- Do not start v0.2 work.

## E2E Rules

`dashboard-agent-autotune` must:

- open the dashboard.
- use `world-agent-goal-input` and `world-agent-autotune-button`.
- assert deterministic success for the current MockLLMProvider path.
- inspect `world-agent-success` and `world-agent-patches`.
- prove the params path changed through `world-params-json` or a Playwright
  test-script API assertion.

`dashboard-timeline-navigation` must:

- generate enough events through UI runtime steps.
- use `timeline-page-size`, `timeline-next-page`, and
  `timeline-prev-page`.
- expand a `timeline-row` through `timeline-row-expand`.
- assert expanded `timeline-event-type`, `timeline-event-source`, and
  `timeline-event-payload` evidence.

Playwright API reads are allowed only inside the E2E test script as
deterministic assertion evidence. They are not Agent operations.

## Live Agent Smoke Rules

Live `dashboard-invalid-param` must run through UI/CLI operation records only.

Required UI targets in `operation-log.jsonl`:

- `dashboard`
- `world-params-path-input`
- `world-params-value-input`
- `world-params-apply-button`
- `world-params-error`

The live run evidence must record these CLI commands in
`result.json.commands` and as `cli` entries in `operation-log.jsonl`:

- `tools/testing/agent_smoke_evidence.py baseline ...`
- `tools/testing/agent_smoke_evidence.py collect --scenario
  dashboard-invalid-param ...`
- `make validate-agent-smoke-result
  RESULT_DIR=test-results/agent-smoke/latest`

Each recorded CLI command must have `exit_code: 0`.

`api-summary.json` must be generated by
`tools/testing/agent_smoke_evidence.py collect`, not manually authored. It must
prove:

- scenario is `dashboard-invalid-param`.
- invalid path is `system.secret`.
- params are unchanged compared with baseline.
- `ui_error_seen` is `true`.

Replacing `test-results/agent-smoke/latest/` is allowed for this package, but
review evidence must state that it replaces the 0.1.8 params-flow latest raw
evidence and that durable params-flow status remains recorded in docs.

## Status Update Rules

After successful implementation:

- `dashboard-agent-autotune` may be marked `implemented`.
- `dashboard-timeline-navigation` may be marked `implemented`.
- `dashboard-invalid-param` may be marked `live-smoke-recorded`.
- `dashboard-params-flow` remains `live-smoke-recorded`, with its 0.1.8
  evidence recorded in docs even if `latest/` now points to invalid-param.
- Full autonomous, persistence/restart, WorldSpec/WorldCell, and agent
  memory/self gaps must remain future-work gaps.

## North Star Check

This package closes tests for existing v0.1 runtime projection behavior. It
does not narrow WorldEngine into a game-specific backend and does not preempt
recursive world, WorldSpec, or agent-continuity roadmap work.

- A later autonomous package may define scorecard-based Codex/test-runner
  verdicts.
- Later roadmap versions may cover persistence/restart, WorldSpec/WorldCell,
  agent memory, and pseudo-self behavior.

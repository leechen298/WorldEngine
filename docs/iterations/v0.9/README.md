## Goal

v0.9 moves WorldEngine from a proved basic lifecycle into the first
LLM-backed lifecycle foundation.

The version goal is to let WorldEngine, not the Validation Client, call a live
provider, turn a user's basic worldview into a public runnable world model,
control bounded world execution, let users guide world-level direction without
directly forcing Agent internals or final outcomes, evolve world parameters
and events through explicit rules, expose public brain-inspired Agent
continuity evidence with memory consolidation rhythms, and provide
checker-backed evidence that the flow works.

In plain terms: v0.9 should make WorldEngine able to create and run a world
with LLM support while keeping the run controllable, inspectable, and safe to
validate.

## Handoff From v0.8

v0.8 closed the basic lifecycle and external-validation readiness boundary.
The current handoff facts are:

- Basic `worldengine-full-lifecycle-autonomous` validation can PASS through the
  official checker after the public provider metadata redaction checker repair.
- The basic flow proves world creation, tick progression, events, snapshots,
  one WorldEngine-backed Agent action, natural-language direction boundary,
  and evidence export.
- The LLM-backed suite is `BLOCKED`, not because the basic product flow is
  broken, but because provider live smoke, LLM-backed world creation,
  rule-linked evolution, event legality, persistent Agent autonomy evidence,
  and LLM-backed checker/schema support do not yet exist.

v0.9 starts from that blocker list. It must not reopen `0.8.9.3`, and it must
not treat planned LLM-backed testing docs as current PASS-capable coverage.

## Scope

Allowed v0.9 scope after reviewed child authorization:

- WorldEngine-owned provider configuration and live smoke calls.
- redacted provider evidence and provider readiness semantics.
- LLM-backed worldview ingestion and public world model generation.
- generated world parameters, rules, constraints, boundaries, and validation
  metadata.
- immediate and run-based worldview fidelity checks.
- bounded runtime controls such as run N ticks, run for world-time duration,
  pause, resume, and max-run limits.
- natural-language world direction that affects only external events and world
  environment trends, not direct Agent private state.
- rule-linked parameter evolution and event legality checks.
- brain-inspired public Agent continuity contracts: perception, working or
  short-term memory, long-term memory summaries, personality summaries, skill
  summaries, intent states, behavior, and event reactions without raw
  chain-of-thought or private memory leakage.
- sleep, rest, or low-activity consolidation cadence for memory, personality,
  and skill updates. Consolidation may span multiple ticks and must not be
  modeled as mandatory per-tick personality or long-term memory mutation.
- external narrative projection and out-of-world diagnostic conversation
  boundaries. These surfaces may help humans or validators inspect the run, but
  they must not become in-world events or Agent memories by default.
- LLM-backed autonomous checker, fixtures, result schema, scorecard, and
  second-Agent review support.
- WorldEngine-to-Validation-Client evidence handoff contracts.

Forbidden v0.9 scope unless a later reviewed package explicitly changes the
roadmap:

- Do not make the Validation Client own provider calls or provider keys.
- Do not store, display, or export API keys, authorization headers, raw prompts,
  raw provider responses, raw provider traces, private Agent memory, raw
  thought, or hidden context.
- Do not let user direction directly set final world facts such as "Agent X is
  dead"; user direction must be transformed into bounded world-level pressure,
  constraints, probability shifts, or external event candidates.
- Do not model Agent personality, long-term memory, or skill drift as automatic
  per-tick updates.
- Do not treat external player-to-Agent diagnostic conversation as in-world
  dialogue, world timeline content, or Agent memory unless a future reviewed
  package explicitly creates such a bridge.
- Do not let narrative text generation mutate canonical world state.
- Do not implement concrete demo worlds, maps, characters, locations,
  resources, story rules, app-specific backend behavior, or product packaging
  in this repository.
- Do not add new runtime features under `backend/worldengine/`.
- Do not claim product readiness, human-quality simulation, consciousness,
  full selfhood, external validation PASS, or LLM-backed lifecycle PASS without
  current-session checker or scorecard evidence.

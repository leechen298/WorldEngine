# v0.9 Plan

Chinese mirror: `v0.9-plan.zh.md`.

Status: reviewed / 0.9.9 implementation complete / verification passed

## Version Name

LLM-backed World Lifecycle Foundation

## Objective

Establish the first WorldEngine version where LLM behavior is owned by the
engine, can create a runnable world from a user's basic worldview, can guide
bounded world evolution through explicit rules, can accept user direction as
world-level guidance, can expose brain-inspired public Agent continuity and
memory-consolidation evidence, can keep narrative and diagnostic conversation
surfaces outside canonical world mutation, and can be validated through
LLM-backed autonomous evidence contracts.

## Planning Authority Boundary

This file is the v0.9 parent roadmap and planned package specification. The
`0.9.x` sections below are route-map specs only. They are not active child
contracts, implementation authorization, evidence execution authorization, or
provider live-call authorization.

Before any `0.9.x` child starts, the agent must create or confirm that child's
complete document set at that time, then pass its review gate.

## Version Boundaries

v0.9 may define or implement after reviewed child authorization:

- provider live smoke through WorldEngine-owned configuration.
- redacted provider evidence.
- public LLM-backed worldview ingestion and world model generation.
- generated world rules, parameters, constraints, validation metadata, and
  runtime-readiness semantics.
- worldview fidelity checks immediately after generation and after bounded
  runtime.
- bounded run controls by ticks, world-time duration, pause, resume, and
  provider/cost limits.
- natural-language world direction as queued world-level guidance.
- rule-linked parameter evolution and event legality.
- brain-inspired Agent continuity contracts covering perception, working or
  short-term memory, long-term memory summaries, personality summaries, skill
  summaries, intent states, behavior, and event reactions.
- sleep, rest, or low-activity consolidation cadence where memory,
  personality, and skill updates may settle across multiple ticks instead of
  being forced into every tick.
- external narrative projection and out-of-world diagnostic conversation
  boundaries for inspection and validation.
- LLM-backed autonomous checker/schema/fixtures/scorecard support.
- public evidence handoff contracts for Validation Client consumption.

v0.9 must not implement:

- Validation Client provider key management or direct LLM calls.
- concrete game/application worlds, names, maps, characters, resources, story
  rules, private validation scenarios, or application-specific backend logic.
- product UI, game packaging, Steam/native distribution, app deployment, or
  external validator implementation.
- raw prompt, raw response, raw provider trace, raw thought, chain-of-thought,
  private Agent memory, private goals, hidden context, or secrets in evidence.
- direct user-imposed final facts that bypass rules and world state.
- automatic per-tick personality, long-term memory, or skill mutation.
- external player-to-Agent diagnostic conversation as in-world dialogue, world
  timeline content, or Agent memory by default.
- narrative text generation that mutates canonical world state.
- new runtime features under `backend/worldengine/`.
- LLM-backed lifecycle PASS without checker/scorecard/second-Agent review
  evidence.

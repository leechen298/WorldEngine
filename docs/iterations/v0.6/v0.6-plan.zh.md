# v0.6 计划

状态：planned / ready for review

## 版本名称

World Generation v1

## 目标

把 WorldEngine 从已评审的 `WorldSpec` loading、runtime-context bridging、
Agent-in-World loop 和 memory substrate 推进到第一层 generic world generation
capability。v0.6 必须从 templates 和 structured AI-assisted generation plans 生成
valid、runnable `WorldSpec` data，并提供 validation、metadata、preview 和 regeneration
support。

## 版本边界

v0.6 可以定义或实现：

- generation request 和 result contracts。
- generic template semantics 和 deterministic template generator core。
- structured generation plan validation，并将其编译为 `WorldSpec`。
- provider-independent AI-assisted generation boundaries，其中 model output 是待验证的
  structured plan。
- generation metadata、provenance、diagnostics、preview 和 regeneration semantics。
- backend schemas、services、API routes、frontend preview UI 和 focused tests，
  但只能在已评审 child package 授权后实现。
- evidence audit、release-candidate 和 final closeout docs。

v0.6 不得实现：

- external validation runner readiness 或 report automation；该范围属于 v0.7。
- first external projection application readiness；该范围属于 v0.8。
- concrete world names、maps、characters、locations、resources、story rules、
  seed data、UI-specific app behavior 或 private validation oracle details。
- durable persistence 或 migrations，除非已评审 v0.6 child 明确授权。
- live external AI-provider behavior，除非已评审 child 明确授权 provider
  configuration、security、failure handling 和 tests。
- `backend/worldengine/` 下的新 runtime features。
- full autonomous validation、external validation readiness、projection readiness 或
  product readiness claims。

## 能力边界拆分

| Capability | v0.6 docs contract | First implementation package |
| --- | --- | --- |
| Generation request/result | 定义 public schema semantics | 是：backend schema/service |
| Generic templates | 定义 template shape 和 constraints | 是：deterministic template core |
| Structured generation plan | 定义 compiler contract | 是：plan compiler |
| AI-assisted generation | 定义 provider-independent plan import | 是：仅 mock/import boundary |
| Metadata/provenance | 定义 required evidence fields | 是：generation result metadata |
| Preview | 定义 bounded inspectable output | 是：backend/API 后接 dashboard |
| Regeneration | 定义 input lineage 和 constraints | 是：bounded regeneration service |
| External validation readiness | 明确 out of scope | 否，v0.7 |
| Projection app readiness | 明确 out of scope | 否，v0.8 |

## 公共接口意图

`0.6.0` 不新增 public runtime APIs 或 implementation files。

未来计划中的 implementation interfaces 可以包括：

- planned schema module：`backend/app/schemas/world_generation.py`。
- planned service module：`backend/app/world/generation.py` 或等价的已批准路径。
- planned API route：`backend/app/api/routes/world_generation.py`。
- planned tests：`backend/app/tests/test_world_generation_*.py`。
- planned frontend surfaces：`frontend/src/components/GenerationPanel.vue`、
  `frontend/src/api/client.ts`，以及只有在已评审 child 授权 frontend work 后才添加的
  focused component/E2E tests。

这些路径只有在相关 child package review 记录 `implementation_authorized: yes` 后才被授权。

## 必需兼容性基线

任何 implementation-bearing v0.6 child 在改变 runtime、schema、API、event、
archive、params、frontend-facing、test、fixture、migration 或 legacy behavior 前，
都必须为 touched surface 提供 current-session evidence，并为 adjacent compatibility
surfaces 提供 focused regression evidence。

Compatibility-sensitive surfaces 包括：

- `WorldSpec`、`WorldCell` 和 `EntityRef`。
- `load_worldspec`、`LoadedWorldSpec`、`WorldSpecLoaderResult` 和
  `WorldSpecLoaderError`。
- `RuntimeContext`、`RuntimeContextSummary`、`build_runtime_context` 和
  `summarize_runtime_context`。
- `RuntimeEngine.get_runtime_context`、`RuntimeEngine.step`、tick/time behavior、
  event emission 和 runtime-context non-leakage。
- `PerceptionFrame`、`ActionIntent`、`ActionResult`、request-scoped `LoopStep` 和
  `POST /world/agent/loop/step`。
- v0.5 working/episodic memory context surfaces。
- API envelope 和 error shape。
- `/runtime/state`、`/runtime/step`、`/world/events`、`/world/event-steps`、
  `/world/agent/params/propose-and-apply` 和 archive behavior。

除非 active child contract 明确允许 breaking change，否则 schema changes 必须是 additive。

## Codex `/goal` 与 Evaluator 模型

`完成 v0.6` 使用 `GOAL_RUNNER.md`、`CURRENT_STATE.md` 和 `CAMPAIGN_PLAN.md`。
Implementation-bearing children 在 closeout 前必须完成 documentation/contract
evaluator、implementation-scope evaluator、code-review evaluator、
validation-evidence evaluator 和 closeout consistency review。

会改变 goal routing、evidence rules、package sequencing、automation-consumption
contracts、release status、validation templates 或 mirror obligations 的
documentation-only children，必须使用 read-only documentation evaluator。

如果 evaluator tooling 不可用或未授权，package 必须保持 `planned / ready for review`
或记录 blocker，不得静默声称 review complete。

### 0.6.7 Dashboard Generation Preview And E2E Smoke

包名：`0.6.7-dashboard-generation-preview-and-e2e-smoke`

状态：planned

类型：mixed or code

目标：在 backend/API generation contracts 稳定后，添加 dashboard-facing generation
preview workflow 和 browser E2E smoke。

存在原因：v0.6 preview support 应该可被 operators inspect，但 dashboard work 必须保持
generic，不能变成 product-specific world builder application。

输入 / 必读资料：

- `0.6.5` API route contract 和 tests。
- `0.6.6` runtime-readiness evidence。

允许修改：

- 添加 generic generation preview UI components 和 API client methods。
- 添加 component tests，覆盖 empty、generating、validation failed、preview ready 和
  regeneration requested states。
- 添加 focused E2E smoke，覆盖 generation preview。
- 更新 frontend scope 相关 docs 和 review evidence。

禁止修改：

- 不得添加 product-specific UI flows、concrete maps、characters、story editors、art、
  sound、packaging 或 external application behavior。
- 不得在 frontend fixtures 中存储 private validation worlds。
- 不得声明 full product readiness、external validation readiness 或 projection readiness。
- 除非明确评审，否则不得触及 backend generation semantics。

预期交付物：

- Generic dashboard preview workflow。
- Focused frontend/component/E2E tests。
- Review evidence 区分 UI preview 与 external projection app readiness。

预期测试 / 验证：

- 针对 changed components/client code 的 focused frontend tests。
- 如果 API client contract 被 exercised，则运行 focused backend/API tests。
- Generation preview 的 E2E smoke。
- 如果 frontend types 或 shared UI surfaces 改变，则运行 build/typecheck。
- Scope 和 diff checks。

兼容性约束：

- Existing dashboard runtime、world、timeline、memory 和 agent panels 保持兼容。
- Existing E2E tests 保持兼容，或只因已评审 UI changes 更新。
- API client behavior 保持 backward compatible。

范围护栏：

- 如果 UI 需要 application-specific world authoring features，则停止。
- 如果 E2E 嵌入 concrete external validation-world oracle data，则停止。
- 如果 frontend changes 缺少 stable reviewed API behavior 支撑，则停止。

退出标准：Dashboard preview workflow 通过 focused UI/API/E2E checks，并诚实记录任何 skipped
broader checks。

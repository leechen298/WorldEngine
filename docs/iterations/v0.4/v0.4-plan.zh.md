# v0.4 计划

状态：final / closeout complete

## 版本名称

世界内 Agent 最小闭环

## 目标

将 WorldEngine 从 v0.3 已验证的 WorldSpec loader 和惰性 runtime context bridge 推进到最小、可审查的世界内 Agent 闭环，同时保持 v0.1 runtime 兼容性，并把后续的记忆、生成、验证和投影里程碑排除在本版本之外。

## 版本边界

v0.4 可以定义或实现：

- 从 runtime state、recent events、world params 和可选 runtime context summary 构建最小 Agent-in-World perception。
- 增量 agent loop schemas。
- `ActionIntent` 和 `ActionResult` 契约。
- 经过校验的 `noop` 和 `params.patch` actions。
- 经已评审 child package 授权后的 request-driven loop orchestration 和 API exposure。
- 被触碰 surface 的聚焦后端测试和兼容性证据。
- evidence audit、release-candidate 和 final closeout docs。

v0.4 不得实现：

- 不得添加记忆、情节记忆、关系状态、自我摘要、反思或人格漂移；这些属于 v0.5。
- 不得添加世界生成；这属于 v0.6。
- 不得添加外部验证 runner 就绪或报告自动化；这属于 v0.7。
- 不得添加投影应用就绪；这属于 v0.8。
- 不得添加具体世界名称、地图、角色、地点、资源、故事规则、seed data、UI 特定应用行为或私有验证 oracle 细节。
- 不得在 `backend/worldengine/` 下新增 runtime feature。

## 必需兼容性基线

任何带实现的 v0.4 child 如果改变 runtime、schema、API、event、archive、params、frontend-facing、test、fixture、migration 或 legacy behavior，必须为被触碰 surface 提供当前会话证据，并为相邻兼容性 surface 提供聚焦回归证据。

兼容性敏感 surface 包括 runtime tick behavior、API envelope、runtime routes、event routes、Event.refs serialization、world params、既有 params-agent endpoint、archive behavior、触碰时的 frontend-facing response shapes，以及 legacy boundary。

## Codex `/goal` 与 Subagent 模型

`完成 v0.4` 使用 `GOAL_RUNNER.md`、`CURRENT_STATE.md` 和 `CAMPAIGN_PLAN.md`。带实现 child closeout 前必须完成 documentation/contract evaluator、implementation-scope evaluator、code-review evaluator、validation-evidence evaluator 和 closeout consistency review。

会改变 goal routing、evidence rules、package sequencing、automation-consumption contracts、release status 或镜像义务的 docs-only child，需要 read-only documentation evaluator。

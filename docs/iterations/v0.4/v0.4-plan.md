# v0.4 Plan

Status: final / closeout complete

## Version Name

Agent-in-World Minimal Loop

## Objective

Move WorldEngine from the v0.3 validated WorldSpec loader and inert runtime context bridge toward the smallest inspectable Agent-in-World loop while preserving v0.1 runtime compatibility and keeping later memory, generation, validation, and projection milestones out of scope.

## Version Boundaries

v0.4 may define or implement:

- minimal Agent-in-World perception from runtime state, recent events, world params, and optional runtime context summary.
- additive agent loop schemas.
- `ActionIntent` and `ActionResult` contracts.
- validated `noop` and `params.patch` actions.
- request-driven loop orchestration and API exposure when authorized by a reviewed child package.
- focused backend tests and compatibility evidence for touched surfaces.
- evidence audit, release-candidate, and final closeout docs.

v0.4 must not implement:

- Do not add memory, episodic memory, relationship state, self-summary, reflection, or personality drift; v0.5 owns that scope.
- Do not add world generation; v0.6 owns that scope.
- Do not add external validation runner readiness or report automation; v0.7 owns that scope.
- Do not add projection application readiness; v0.8 owns that scope.
- Do not add concrete world names, maps, characters, locations, resources, story rules, seed data, UI-specific app behavior, or private validation oracle details.
- Do not add new runtime features under `backend/worldengine/`.

## Required Compatibility Baseline

Before any implementation-bearing v0.4 child changes runtime, schema, API, event, archive, params, frontend-facing, test, fixture, migration, or legacy behavior, that child must provide current-session evidence for the touched surface and focused regression evidence for adjacent compatibility surfaces.

Compatibility-sensitive surfaces include runtime tick behavior, API envelope, runtime routes, event routes, Event.refs serialization, world params, the existing params-agent endpoint, archive behavior, frontend-facing response shapes when touched, and the legacy boundary.

## Codex `/goal` And Subagent Model

`完成 v0.4` uses `GOAL_RUNNER.md`, `CURRENT_STATE.md`, and `CAMPAIGN_PLAN.md`. Implementation-bearing children require documentation/contract evaluator, implementation-scope evaluator, code-review evaluator, validation-evidence evaluator, and closeout consistency review before closeout.

Documentation-only children that change goal routing, evidence rules, package sequencing, automation-consumption contracts, release status, or mirror obligations require a read-only documentation evaluator.

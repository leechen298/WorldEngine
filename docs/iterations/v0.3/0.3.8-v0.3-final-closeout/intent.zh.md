# Intent

## 问题

v0.3 已有发布候选包，但最终发布状态必须等到评审批准、阻塞项分类和收口
证据在独立包中记录后才能声明。如果没有窄范围的最终收口契约，状态更新可能
漂移成功能清理、未评审证据声明，或过早的 v0.4 交接措辞。

## 目标

创建一个文档包，定义 0.3.7 发布候选评审之后 v0.3 如何收口。该包需要让
最终收口验收可测试，列出允许的状态更新，并确保实现、运行时、schema、API、
前端、fixture、migration 和测试文件都不在范围内。

## 非目标

- 文档阶段不声明 v0.3 最终完成。
- 不重新运行或修补运行时、API、前端、schema、fixture、migration 或测试
  实现行为。
- 不实现 v0.4 世界内 Agent 行为。
- 不添加记忆、自我连续性、生成、投影、产品 UI、游戏 UI、具体演示世界、
  外部验证世界或外部仓库。
- 不把开放的 P3 交接项改写成已完成工作。

## 为什么现在做

0.3.8 是 v0.3 里程碑序列中计划的最后一个包。它位于发布候选包之后，用于
给评审者一个独立、可评审的门禁，以决定 v0.3 是否可以从 planned / not
released 进入最终收口状态。

## 与北极星的关系

本包通过证据、兼容性评审和范围边界关闭加载器与运行时桥接里程碑，从而保护
WorldEngine 的递归世界方向。它不会把引擎收窄成应用专用逻辑、具体 fixture
世界、NPC 聊天或产品 UI。

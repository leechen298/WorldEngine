# Contract

## 公开概念

- 最终收口：在发布候选包被接受且阻塞项被清除或明确分类后，将 v0.3 标记为
  最终状态的仅文档动作。
- 最终评审决定：决定最终收口是否可以继续的人工 / ChatGPT 批准、拒绝或有
  条件接受。
- 阻塞问题：阻止最终收口的未解决 P1/P2 问题。
- 已接受交接项：预计仅限 P3 的非阻塞问题，以明确收口措辞保留给 v0.4 或
  后续工作。
- 历史证据：早期包评审中记录的命令和测试结果，必须与 0.3.8 当前会话运行
  的命令区分。

## 兼容性约束

- 运行时行为不得改变。
- schema 行为和校验行为不得改变。
- 事件存储、事件分页、归档行为、分组行为、参数行为和 API 响应行为不得
  改变。
- 前端行为不得改变。
- fixture、migration 和测试实现文件不得改变。
- `backend/worldengine/` 必须保持未触碰。
- 只有在获得批准且不存在未解决 P1/P2 问题时，才能声明最终发布状态。
- 最终收口措辞必须区分历史包证据和 0.3.8 当前会话验证。

## 允许变更

- 新增或更新
  `docs/iterations/v0.3/0.3.8-v0.3-final-closeout/` 下的文件。
- 在评审批准后更新 `docs/releases/v0.3.md` 和
  `docs/releases/v0.3.zh.md`。
- 更新 `docs/iterations/v0.3/README.md` 和
  `docs/iterations/v0.3/README.zh.md`。
- 更新 `docs/iterations/v0.3/v0.3-plan.md` 和
  `docs/iterations/v0.3/v0.3-plan.zh.md`。
- 如果最终评审改变问题状态、阻塞分类或 v0.4 及后续交接措辞，可更新
  `docs/iterations/v0.3/findings.md`。
- 运行只读文档检查、状态一致性检查、发布措辞检查、具体演示锚点扫描、
  P1/P2 阻塞项检查和变更文件范围检查。

## 禁止变更

- 不修改运行时服务、schema、API 路由、应用装配、事件日志行为、归档行为、
  持久化行为、参数行为、Agent 行为、前端实现、fixture 文件、migration 文件
  或测试实现文件。
- 不修改 `backend/worldengine/`。
- 不实现新的 WorldSpec 加载器行为、RuntimeEngine 迁移、运行时桥接行为、
  生成、投影、世界内 Agent 闭环、记忆、自我连续性、resolver 或因果行为。
- 不创建外部 fixture 或验证仓库。
- 不添加具体外部世界名称、角色、地点、资源、剧情规则、种子数据、UI 选择器、
  私有 runner 状态或应用专用后端逻辑。
- 除非命令或流程在当前会话运行，不得声明测试、构建、运行时行为、API 行为或
  前端行为通过。
- 不把 v0.4 标记为可实现；v0.4 需要自己的已评审迭代包。

## 验收要求

- 本包包含 README、intent、contract、technical design、test plan、plan 和
  review 文档的英文与中文镜像。
- 文档阶段，包 README 和 v0.3 里程碑索引将 0.3.8 标记为
  `ready for review`。
- 最终收口实现明确受 0.3.7 发布候选批准约束。
- 最终状态要求说明未解决 P1/P2 问题会阻塞收口。
- 开放 P3 问题只有在最终评审接受为非阻塞时，才可保留为交接项。
- 验证要求包括 `git diff --check`、最终状态措辞检查、状态一致性检查、未解决
  P1/P2 阻塞项检查、变更文件范围检查和具体演示锚点扫描。
- 除非在当前 0.3.8 会话运行，否则不声明后端、前端、API smoke、E2E、Agent
  smoke、运行时、schema 执行、fixture、migration 或测试实现检查通过。
- 包文档和状态文档的英文与中文镜像保持同步。

## 北极星检查

本包通过证据和边界关闭 WorldSpec 加载器与运行时桥接里程碑，保护
WorldEngine 作为通用递归世界引擎的定位。它不添加具体世界、产品 UI、私有
验证内部细节或运行时捷径。

## 范围外后续

- v0.4 只能通过单独的 v0.4 包契约启动。
- 新的运行时/API/前端回归证据应属于明确要求它的已评审包，除非最终评审者
  在收口期间明确要求。
- 机器可读外部验证报告强化仍属于后续验证准备阶段。
- 任何新发现的 P1/P2 缺口必须成为阻塞项或单独评审的后续工作，不能成为未评审
  的 0.3.8 实现补丁。

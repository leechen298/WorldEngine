## 契约对齐与不变量

- 每个能力声明必须引用证据来源，或标记为限制 / 问题。
- 现有运行时、schema、API、事件、归档、参数、前端、fixture、迁移、测试和
  旧路径行为必须保持不变。
- P1/P2 问题不能被隐藏或通过措辞降级。
- v0.3 在 0.3.8 收口前仍不是最终发布。

## 文档结构

- `v0.3-release-candidate-bundle.md`：包含范围、包矩阵、兼容性矩阵、证据映射、
  问题、假设、风险和收口前置条件的人类可读候选包。
- `final-review-bundle.md`：按模板组织的评审交接，包含变更文件、契约映射、
  禁止变更确认、命令、兼容性评审、问题和 ChatGPT 评审请求。
- 包文档：英文和中文的 README、意图、契约、技术设计、测试计划、计划和评审。

无。

## 运行时 / 服务设计

无。本包不执行或修改运行时服务。

## 兼容性

兼容性通过范围控制保持不变。本包记录加载器、桥接层、运行时、API、事件、
归档、参数、schema、fixture、前端可见和旧路径边界的历史证据。任何本会话未运行
的命令都必须保持为历史证据，而不是新的通过声明。

## 风险

- 发布候选声明可能夸大历史证据；必须通过证据可追溯检查和评审包映射发现。
- 措辞可能暗示最终发布；必须执行发布状态表述检查。
- 组装期间可能发现新的 P1/P2；必须记录，并阻塞 0.3.8，直到解决或被明确接受。

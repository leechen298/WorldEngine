# Intent

## 问题

`0.3.2` 已经为 WorldEngine 提供了最小加载器，可以加载已验证的通用
`WorldSpec` 数据，但仍未定义这些已加载数据如何接近运行时状态。如果没有已
评审的桥接契约，实现阶段可能会把原始 `WorldSpec` 塞进运行时 payload，把
`WorldCell` 误解为运行时模块，或破坏 v0.1 的 tick、事件、参数、归档、API
和前端兼容性。

## 目标

创建可评审的运行时上下文桥接契约，定义输入、派生上下文形状、运行时边界、
兼容性证据、错误类别、假设、风险和后续最小桥接实现的验证要求。

## 非目标

- 不实现运行时上下文桥接层。
- 不改变 `RuntimeEngine`。
- 不把已加载数据接入运行时行为。
- 不新增 API 路由或响应字段。
- 不发出事件，也不把原始 `WorldSpec` 放进事件 payload。
- 不改变参数、归档、持久化、前端、fixture、migration 或旧路径行为。
- 不把 `WorldCell` 直接映射为 `WorldModule`。
- 不实现世界生成、世界内 Agent 闭环、记忆、自我连续性、投影、剧情生成或
  NPC 聊天行为。

## 为什么现在做

v0.3 是从 schema 和加载器基础走向运行时上下文的桥接版本。加载器必须保持
数据边界，运行时工作必须保留 v0.1 兼容性。因此在 `0.3.4` 添加任何可选
运行时上下文路径前，必须先定义契约。

## 北极星对齐

本包为结构化世界规格接近运行时准备通用路径，同时避免把 WorldEngine 收窄为
具体游戏、演示世界、外部验证 fixture 或产品后端。

## 假设

- `0.3.2` 加载器输出或经评审的等价物是唯一桥接输入。
- 初始运行时上下文在驱动行为前，也可以作为可选、惰性的元数据有价值。
- 现有 v0.1 运行时状态和模块行为是 v0.3 桥接工作的兼容性基线。
- 未来任何从 `WorldCell` 到运行时模块的映射都需要单独评审的包。

## 未决风险

- 后续桥接实现可能为方便而暴露过多原始 `WorldSpec` 数据。
- 如果把上下文存入 `RuntimeEngine`，可能意外改变序列化运行时响应。
- 从 `WorldSpec` 复制的 metadata 如果不保持中立，可能获得领域特定含义。
- 前端可见形状的兼容性证据可能需要比最小后端桥接实现更广的测试。

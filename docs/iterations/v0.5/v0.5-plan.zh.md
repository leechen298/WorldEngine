# v0.5 计划

状态：final / closeout complete

## 版本名称

Memory And Self-Continuity Substrate

## 目标

把 WorldEngine 从 v0.4 request-driven Agent-in-World loop 推进到第一层可检查的
memory 与 self-continuity substrate，同时保持 v0.4 loop compatibility，并把
generation、external validation readiness 和 projection application readiness 排除在范围外。

## 版本边界

v0.5 可以定义或实现：

- 带 provenance、bounded lifetime semantics 和 inspectable sources 的 working memory
  records。
- 连接 events、ticks、world time 和 action outcomes 的 episodic memory records。
- relationship state schema semantics。
- self-summary schema semantics。
- reflection record schema semantics。
- personality drift signal schema semantics。
- 只有在已评审 child package 授权后，才实现第一层 generic in-memory substrate。
- 只有在已评审 child package 授权后，才把 bounded read-only memory context 接入
  Agent Loop。
- 针对被触及 surfaces 的 focused backend tests 和 compatibility evidence。
- evidence audit、release-candidate 和 final closeout docs。

v0.5 不得实现：

- world generation；该范围属于 v0.6。
- external validation runner readiness 或 report automation；该范围属于 v0.7。
- projection application readiness；该范围属于 v0.8。
- concrete world names、maps、characters、locations、resources、story rules、
  seed data、UI-specific app behavior 或 private validation oracle details。
- frontend product behavior，除非后续已评审 v0.5 child 明确授权。
- durable persistence 或 migrations，除非后续已评审 v0.5 child 明确授权。
- `backend/worldengine/` 下的新 runtime features。

## 能力边界拆分

| Capability | v0.5 docs contract | First implementation package |
| --- | --- | --- |
| Working memory | 定义 concept、provenance、bounded read/write semantics | 是：additive schema + generic in-memory substrate |
| Episodic memory | 定义 event-linked episode semantics | 是：additive schema + generic in-memory substrate |
| Relationship state | 只定义 schema semantics | 暂不实现 behavior |
| Self-summary | 只定义 schema semantics | 暂不实现 summarization behavior |
| Reflection records | 只定义 schema semantics | 暂不实现 automatic reflection |
| Personality drift signals | 只定义 schema semantics | 暂不实现 action modifier |

## 公共接口意图

`0.5.0` 不新增 public runtime APIs 或 implementation files。

未来计划中的 implementation interfaces 可以包括：

- planned schema module：`backend/app/schemas/agent_memory.py`。
- planned service/store module：`backend/app/agent/memory.py` 或等价的已批准路径。
- planned tests：`backend/app/tests/test_agent_memory_*.py`。
- 只有在 `0.5.3-memory-context-loop-integration` 完成评审和授权后，才允许对
  `PerceptionFrame` 做 bounded additive extensions。

## 必需兼容性基线

任何 implementation-bearing v0.5 child 在改变 runtime、schema、API、event、
archive、params、frontend-facing、test、fixture、migration 或 legacy behavior 前，
都必须为 touched surface 提供 current-session evidence，并为 adjacent compatibility
surfaces 提供 focused regression evidence。

Compatibility-sensitive surfaces 包括：

- `PerceptionFrame`。
- `ActionIntent`。
- `ActionResult`。
- request-scoped `LoopStep`。
- `POST /world/agent/loop/step`。
- `/world/agent/params/propose-and-apply`。
- runtime tick 和 world time behavior。
- API envelope 和 error shape。
- `/runtime/state`、`/runtime/step`、`/world/events`、`/world/event-steps`。
- world params 和 params apply behavior。
- archive behavior。
- `Event.refs` optional serialization。

除非 active child contract 明确允许 breaking change，否则 schema changes 必须是 additive。

## Codex `/goal` 与 Subagent 模型

`完成 v0.5` 使用 `GOAL_RUNNER.md`、`CURRENT_STATE.md` 和 `CAMPAIGN_PLAN.md`。
Implementation-bearing children 在 closeout 前必须完成 documentation/contract
evaluator、implementation-scope evaluator、code-review evaluator、
validation-evidence evaluator 和 closeout consistency review。

会改变 goal routing、evidence rules、package sequencing、automation-consumption
contracts、release status、validation templates 或 mirror obligations 的
documentation-only children，必须使用 read-only documentation evaluator。

# v0.8 Plan

状态：planned / ready for review

## Version Name

Minimum Proved Working WorldEngine / External Validation Readiness

## Objective

准备 WorldEngine 的 core-side contracts、public observable surfaces 和 evidence
boundaries，让独立的 external validation function 可以验证 WorldEngine 是否达到
minimum normally working state。

v0.8 不在本仓库内实现 external validator，也不实现第一个 external product
application。它要让 core engine 足够一致、可观察，供外部验证使用，同时把 validation
scenarios、connection details、oracle logic、concrete app data 和 product-specific
behavior 留在 core repository 外。

## Planning Authority Boundary

本文件是 v0.8 parent roadmap 和 planned package specification。下面的 `0.8.x`
sections 只是 route-map specs。它们不是 active child contracts，不是
implementation authorization，不是 evidence execution authorization，也不是
closeout evidence。

任何 `0.8.x` child 开始前，agent 必须在当时创建或确认该 child 的 complete
document set，然后通过 review gate。若 implementation 暴露设计缺口，必须停止
implementation，更新当前 child 的 `contract.md`、`technical-design.md`、
`test-plan.md`、`plan.md` 和 `review.md`，并在 updated package reviewed 之后才可继续。

Post-closeout v0.7 code review
`docs/testing/results/2026-06-02-v0.7-code-review.md` 记录了 blocking findings。
v0.8 packages 必须用 authorized package 的 current-session evidence 修复受影响
dependency surfaces，或先 route 到 narrow v0.7 repair，或把这些 findings 记录为
blockers。不得静默使用 v0.7 closeout 作为 clean pass、minimum working-state PASS 或
external validation readiness PASS。

## Version Boundaries

v0.8 可在 reviewed child authorization 之后定义或实现：

- minimum normally working WorldEngine claim semantics。
- external validation 所需的 core-side observable public surfaces。
- generation -> runtime -> Agent loop readiness boundaries。
- bounded memory-context 和 event evidence requirements。
- additive、generic read-only projection/read-model APIs 或 payload helpers。
- external-validation handoff contract fields，用于标识 public surfaces、evidence
  references、redaction status 和 blockers。
- provider-boundary、credential、mock fallback 或 gated live-smoke semantics，只有
  active child 明确拥有该范围时才可处理。
- 绑定 public engine contracts 的 core-side smoke 和 compatibility evidence。
- evidence audit、release-candidate 和 final closeout documents。

v0.8 不得实现：

- external validation function。
- external projection application 或 first product application。
- product-specific UI、routing、packaging、deployment、application state 或 backend
  logic。
- concrete app worlds、names、maps、locations、characters、resources、story rules、
  seed data、private transcripts、UI selectors、hidden reset APIs、private oracle
  behavior、private runner state、private external repo paths、provider traces 或
  secrets。
- 没有 current-session evidence 时，不声明 external validation PASS、external
  consumer PASS、product readiness、runtime PASS、API PASS、frontend PASS、E2E
  PASS、Agent smoke PASS、autonomous PASS 或 generation-quality PASS。
- durable persistence、migrations、live provider behavior、active generated-world
  runtime execution，或 `backend/worldengine/` 下的新 runtime features，除非 active
  child 明确授权该范围。

## Public Interface Intent

Parent v0.8 documentation package 不新增 public runtime APIs、schemas、checker
code、frontend routes 或 implementation files。

Planned future interfaces 可能包括：

- `docs/contracts/` 下 planned minimum working-state contract。
- `docs/contracts/` 下 planned core observable surface contract。
- approved `docs/contracts/` 或 `docs/testing/` path 下的 planned external-validation
  handoff manifest 或 report shape。
- 只有在 package review 记录 `implementation_authorized: yes` 之后，才可在 approved
  test/checker path 下添加 planned checker 或 helper code。
- 只有 reviewed package 证明它们是 generic engine contracts、不是 product-app 或
  external-validator behavior 后，才可添加 planned backend/API read-only projection
  endpoints。

这些路径在相关 child package review 记录 `implementation_authorized: yes` 或明确授权
documentation-only contract changes 前，都不被授权。

## Required Compatibility Baseline

任何 implementation-bearing v0.8 child 修改 runtime、schema、API、event、archive、
params、frontend-facing、test、checker、fixture、migration 或 legacy behavior 之前，必须为
touched surface 提供 current-session evidence，并为 adjacent compatibility surfaces 提供
focused regression evidence。

Compatibility-sensitive surfaces 包括：

- v0.7 external validation report schema/checker semantics。
- v0.7 readiness manifest schema/checker semantics。
- v0.7 projection consumer contract 与 projection read-model schema/checker semantics。
- `WorldSpec`、`WorldCell`、`EntityRef`。
- `load_worldspec`、runtime-context bridge 和 `RuntimeEngine` compatibility。
- runtime state、event timeline、archive、params、Agent loop、memory context 和
  generation readiness public surfaces。
- API envelope 和 error shape。
- `/runtime/state`、`/runtime/step`、`/world/events`、`/world/event-steps`、
  `/world/agent/loop/step`、archive routes 和 `/world/generation/*`。

Schema 和 API changes 必须 additive，除非 active child contract 明确允许 breaking
change。

## Codex `/goal` And Evaluator Model

`完成 v0.8` 使用 `GOAL_RUNNER.md`、`CURRENT_STATE.md` 和 `CAMPAIGN_PLAN.md`。
Implementation-bearing children 在 closeout 前需要 documentation / contract
evaluator、implementation-scope evaluator、code-review evaluator、
validation-evidence evaluator 和 closeout consistency review。

Documentation-only children 如果改变 process rules、package sequencing、evidence
rules、automation-consumption contracts、release status、validation templates、report
schemas、projection contracts、readiness taxonomy 或 mirror obligations，需要
read-only documentation evaluator。

如果 evaluator tooling 不可用或未授权，package 必须保持 `planned / ready for
review` 或记录 blocker。不得静默声称 review complete。

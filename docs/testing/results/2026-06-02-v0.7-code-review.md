## Findings

### P1 - External validation pass reports can carry accepted P1/P2 findings

File: `tools/testing/validate_external_validation_report.py`

The checker treats `accepted` as a resolved finding status. A `pass` report with
`unresolved_findings=[{"severity":"P1","status":"accepted"}]` currently returns
no errors. This violates the `0.7.2` contract requirement that `pass` is valid
only when no unresolved P1/P2 finding remains.

Suggested direction:

- Treat only genuinely closed statuses as non-blocking for `pass`.
- Add focused tests for accepted P1 and accepted P2 findings.

### P1 - External validation report redaction scan misses real private paths and UI selectors

File: `tools/testing/validate_external_validation_report.py`

The redaction scan primarily detects synthetic sentinel strings. A report string
containing `data-testid=...` and a local `/Users/...` path can still validate
with no errors. This violates the `0.7.2` redaction-risk scan requirement for
obvious private paths, UI selector markers, hidden reset markers, oracle
internals, seed-data markers, transcripts, and non-redacted external event
payload markers.

Suggested direction:

- Add real generic marker detection for common UI selectors, absolute local
  paths, hidden reset terms, oracle terms, transcript terms, and event payload
  terms.
- Keep tests abstract and generic; do not introduce concrete external world
  details.

### P1 - Readiness manifest checker allows private commands and private-detail text

File: `tools/testing/validate_readiness_manifest.py`

The manifest checker only requires `evidence_references[*].command` to be a
non-empty string, and its private-detail scan is sentinel-only. A command such
as `python /Users/alice/private-suite/run.py` and compatibility text containing
a private local path currently validate with no errors. This violates the
`0.7.3` contract that the manifest must not contain private paths, private
runner state, UI selectors, oracle internals, transcripts, or non-redacted
event payloads.

Suggested direction:

- Apply public path and forbidden-detail checks to command strings and all
  manifest text surfaces.
- Add regression tests for private commands and non-sentinel leaked details.

### P2 - Projection read-model checker can allow private application state summaries

File: `tools/testing/validate_projection_read_model_contract.py`

Allowed field names pass when they use an approved suffix and avoid the current
forbidden term list. `private_application_state_summary` currently validates
because `private` and `application_state` are not forbidden terms. This weakens
the `0.7.4` contract boundary that projection read models must not expose
private application state.

Suggested direction:

- Expand forbidden field terms to include private application state language.
- Add focused tests for private/application-state fields with otherwise valid
  suffixes.

### P2 - Public JSON schemas are looser than checker and contract semantics

Files:

- `docs/testing/external-validation-report-schema.json`
- `docs/contracts/v0.7-readiness-manifest-schema.json`

The public schemas encode shape more than behavior. Consumers that validate
only against JSON Schema can accept inputs that the Python checkers and package
contracts would reject, including weak PASS reports or over-claimed manifest
evidence statuses.

Suggested direction:

- Either tighten the schemas where JSON Schema can express the constraint, or
  document that checker execution is authoritative for semantic validation.
- Add tests that demonstrate schema-valid but checker-invalid cases if this
  split remains intentional.

### P3 - Template and status text drift

Files:

- `docs/validation-report-template.md`
- `docs/contracts/projection-read-model-contract.md`

The validation report template is not directly isomorphic with the machine
report fields, which can make manual-to-JSON conversion error-prone. The
projection read-model contract status still says `ready for implementation
evidence / v0.7.4`, while the package review is already complete.

Suggested direction:

- Add machine-field mapping hints to the template.
- Synchronize the projection read-model contract status text with the package
  review state.

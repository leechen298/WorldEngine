Status: proposed / not executed

## 一句话结论

v0.7 的核心不是外部验证套件已经通过，也不是第一个 projection
application 已经 ready；它是把 WorldEngine 对外部验证和投影消费者可用的公共合约、
redacted report、readiness manifest、projection read model、checker 和证据边界准备好：

```text
public contracts
  -> redacted validation report schema/checker
  -> readiness manifest schema/checker
  -> projection read-model schema/checker
  -> compatibility evidence and claim taxonomy
```

所以 v0.7 测试必须先证明公共 checker 和 redaction 边界可靠，再证明旧的 runtime、
Agent loop、memory、generation、dashboard、E2E 和 Agent-assisted 测试面没有被破坏。

当前已有一个重要边界：`docs/testing/results/2026-06-02-v0.7-code-review.md`
记录了 v0.7 code review 的阻塞发现，包括 external validation report checker、
readiness manifest checker、projection read-model checker 和 public schema/contract
语义偏松的问题。后续执行 v0.7 clean pass 或产品能力验证前，必须先用窄范围修复包处理
这些 P1/P2，或在验证报告中明确把它们记录为 blocker。本文档本身不是 PASS verdict。

## 当前状态边界

`docs/iterations/v0.7/CURRENT_STATE.md` 标记 v0.7 为 `final / closeout complete`，
但它的 final evidence 只覆盖文档、checker、manifest、projection read-model contract、
JSON parse、格式和 scope guard 等 v0.7 公共合约面。

当前 v0.7 final closeout 明确不声明：

- runtime behavior passed。
- API behavior passed。
- frontend behavior passed。
- E2E passed。
- live Agent smoke passed。
- full autonomous runner 或 full autonomous suite passed。
- external validation suite passed。
- projection application readiness passed。
- product readiness passed。
- generation-quality passed。
- v0.8 readiness。

因此，本测试方案把 v0.7 分成两层：

- v0.7 readiness contract/checker 层：必须先消除当前 code review 发现的 P1/P2。
- 截止 v0.7 的整体产品能力层：必须另外运行 backend、frontend、E2E、Agent smoke、
  autonomous saved-result、external redacted report intake 等检查，不能从 final closeout 推断。

## 已知阻塞和风险

| ID | 严重级别 | 风险 | 需要的测试门槛 |

  setup/reset、UI/API assertions、event/log cross-check、failure-path assertions、

  “Agent smoke 场景详单”和“Codex/test-runner autonomous 场景详单”。

- Future runner must execute scenarios from documented goals, not only validate saved artifacts.

  scorecard output.
- Future full-suite PASS requires every selected autonomous scenario result directory to pass checker

- Until such runner exists and is run in the current session, report this layer as `out_of_scope` or

Manual observation is allowed only as supporting evidence:

- screenshots, console notes, transcripts, and human-written observations may explain a failure,

- manual observation must not be the PASS source for E2E, Agent smoke, autonomous, external suite,
  projection readiness, or product readiness.
- if a manual observation contradicts a checker, Playwright assertion, or command output, the command
  or checker result wins until a new current-session command proves otherwise.

## Agent 自主测试定义

本方案采用的 Agent 自主测试定义如下：

- 这里的 `Agent` 是 Codex/test-runner agent 作为测试执行者操作 WorldEngine，不是
  WorldEngine 未来世界里的 in-world Agent。
- 完整 Agent 自主测试是 Codex 像真实测试用户一样，拿到一个目标后自主决定步骤，操作网页、
  调用公开 API、读取公开状态和日志，用黑盒/灰盒方式验证完整功能链路。
- 允许的 API 调用必须是公开产品/API 合同的一部分，例如 `/runtime/state`、`/runtime/step`、
  `/world/params`、`/world/events`、`/world/agent/loop/step`、`/world/generation/*`、
  v0.7 public checker/manifest/report endpoints or CLI equivalents。不能调用 hidden reset API、
  private oracle、private fixture hook、数据库内部状态或外部验证世界私有接口。
- Agent smoke 是基础 UI/CLI 操作 smoke，步骤相对固定，PASS 来源是 deterministic
  checker。
- Minimal autonomous saved-result validation 是当前已经具备的能力：测试 Agent 可以按
  documented goal 选择步骤，但当前仓库的旧 checker 只验证已保存的 result directory，并且
  目前把 direct API operation 从 Agent operation log 中排除；这比用户定义的完整 Agent
  自主测试窄。
- Full autonomous runner/full suite 是未来能力：runner 应从 scenario goal 启动，允许测试
  Agent 在边界内自主规划、操作网页、调用公开 API、自动产出 artifacts，并由
  scorecard/checker 判定。当前 v0.7 不能声称它已经存在或通过。
- Codex 自然语言观察、人工截图解释、transcript 摘要都不能直接决定 PASS；它们只能作为
  supporting evidence。PASS 必须来自 checker 命令。

所以本方案里的 Agent 自主测试用例分三类：

- `AUTO-SAVED-V07-*`: 当前可验证的 saved-result checker cases。
- `AUTO-FULL-V07-*`: 用户定义的完整 Agent 自主测试 cases，允许网页操作和公开 API 调用；当前
  需要协议/checker 扩展后才能自动判 PASS。
- `AUTO-FUTURE-V07-*`: full autonomous runner/full-suite infrastructure cases，只能作为未来
  实现或 blocked/out-of-scope gate，不能在当前 v0.7 验证中写成 PASS。
